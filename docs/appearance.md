# 外观与配色

当前提供跟随系统、浅色、深色、樱花浅色、海盐蓝、松石绿、暖砂岩、石墨夜。外观草稿即时预览，点击设置页顶部「保存设置」后由 Rust 写入配置。离开设置页会恢复已保存的主题。

## 粉色主题复审

原版的画布、侧栏、边框、次级按钮与选中背景同时染粉，区域层次较弱；高饱和玫红又在柔灰画面中显得突出。调整为接近中性的暖灰画布、白色内容面板与更低饱和莓粉强调色；普通操作保持中性，导航选中增加边缘标记。原截图中发白的开关和保存按钮属于浏览器预览禁用态，不能当作正常态颜色不足的证据。

主题卡原先只有图标，难以比较配色；现在用同一套颜色变量绘制侧栏、画布、面板与按钮的缩略预览，附带名称和风格说明。名称位于预览外，始终使用当前宿主的文字颜色。宽屏四列，小于等于1000px时两列；保存按钮放在设置页标题旁，避免新增主题后被推到页面底部。

## 颜色分工

| 主题 | 设计定位 |
|---|---|
| 樱花浅色 | 暖灰留白，低饱和莓粉用于操作和选中状态 |
| 海盐蓝 | 冷中性画布、蓝灰侧栏、深蓝主操作 |
| 松石绿 | 浅雾绿结构、深青绿强调；成功仍以文字和状态图标表达 |
| 暖砂岩 | 暖白面板、浅砂画布、棕铜强调；不与警告角色合并 |
| 石墨夜 | 中性石墨灰表面与浅青绿操作，区别于原蓝灰深色 |

`apps/framework/frontend/src/themes.css` 是颜色的单一来源，宿主、模块构建和缩略预览共用。主题只定义颜色，不在主题分支中改变布局或字体。`--border` 用于区域分隔，`--control-border` 用于控件边界，`--on-accent` 定义主按钮文字；成功、失败与未提交状态保留独立含义。侧栏焦点环使用适配侧栏的颜色，不直接沿用内容区焦点色。

本轮检查正常文字与按钮字的关键色对达到4.5:1、焦点及控件边界关键色对达到3:1；这是选定语义色对的数值检查，不代表整个应用已通过完整可访问性审计。禁用控件、半透明装饰和第三方页签须按实际上下文另行检查。

## 兼容与扩展

SDK 的 `SUPPORTED_APPEARANCES` 管理可解析外观 ID，`getBaseTheme()` 为旧 SDK 保留 light/dark 回退，graphite 使用 dark。旧包不识别新 appearance 时仍可打开，不能用新增外观破坏协议1。包内容变化要升级包版本；宿主升级不会擅自修改用户当前版本选择。

增加配色时同步 SDK、Rust设置枚举、设置选项、CSS与默认配置边界检查；覆盖保存/重读、未知值保护、明暗回退，以及真实预览。颜色文件已纳入模块构建缓存指纹，不能因复用缓存而交付过时配色。实际运行与构建证据见 [验证记录](verification.md)。
