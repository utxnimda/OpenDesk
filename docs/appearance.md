# 界面风格与宠物

当前本地版本为 0.15.0，尚未发布。设置分为「风格与配色」「宠物陪伴」「窗口行为」三类；宠物页只选择角色，其余宠物偏好在宠物右键菜单面板中调整。界面风格 `uiStyle` 与配色 `theme` 分开保存，`personalization` 仅承载通用宠物偏好。背景图片导入、背景显示、粒子和氛围调节已移除；原有六种风格保留并新增薄荷奶油，阿宝与阿沐的既有素材不变。选择风格不自动覆盖配色，「使用建议配色」是独立操作。

## 七种界面风格

| ID | 风格 | 布局与视觉重点 | 建议配色 |
|---|---|---|---|
| `simple` | 简洁 | 保留原侧栏、欢迎区和基础内容分区 | 跟随系统 |
| `codex` | Codex | 轻量侧栏、较多留白、突出主要内容和工具入口 | 浅色 |
| `cursor` | Cursor | 参考 Cursor IDE 的活动栏、工作区标签、紧凑面板和状态栏 | 石墨夜 |
| `web` | 现代 Web | 悬浮侧栏、卡片入口、宽阔画布与清楚的层级 | 海盐蓝 |
| `anime` | 二次元 | 顶部导航、柔彩、圆润面板与静态装饰 | 樱花浅色 |
| `glass` | 深海透明 | 深蓝黑半透明、青色细边、低圆角紧凑分区与顶部标签栏 | 深色 |
| `mint` | 薄荷奶油 | 浅粉/薄荷静态柔雾背景、深青文字、大圆角卡片、轻导航与中心内容列 | 浅色 |

Codex 与 Cursor 为视觉参考名称，不代表接入这些产品。参考来源为 [Codex 官方产品页](https://openai.com/codex/) 与 [Cursor 官方界面介绍](https://cursor.com/blog/cursor-3)；Cursor 风格采用其 IDE 的紧凑工作区方向。七种风格共用实际功能目录和导航操作，不模拟聊天、代码编辑或不存在的任务统计。装饰不承载状态、不遮挡文字与操作。

深海透明参考游戏调试面板的紧凑组织：深蓝黑半透明底色配青色细描边，区域采用低圆角、细分隔与顶部标签栏。它是静态界面风格，`glass` 存储 ID 保持不变，建议配色为 `dark`；不增加背景图、光晕动画或氛围调节。该呈现方向在 0.9.0 中引入，当前版本继续保留。

薄荷奶油的建议配色为 `light`：浅粉与薄荷静态渐变承托白色卡片，卡片采用约 26 px 圆角、轻阴影和宽松留白，正文偏深青，选中态与开关用薄荷色。内容列居中、导航轻量，角色卡保留真实头像与说明。选择 `dark`、`graphite` 或其他配色时保留各主题的语义颜色，不自动改回浅色。七项风格选择器按可用宽度自动换列。该风格只有静态 CSS，不读取用户图片，不恢复背景或氛围设置，也不引入参考图中的角色、声音或其他业务内容。

`apps/framework/frontend/src/workbench-styles.css` 管理宿主布局及宿主、模块共用的静态控件风格，根元素的 `data-ui-style` 选择风格；`apps/framework/module-sdk/src/surface.css` 管理模块独立文档的尺寸与滚动边界。`themes.css` 提供基础颜色。工作台的模块名称、所选版本和可打开数量均来自宿主目录；浏览器预览、读取中与没有可打开功能有独立显示状态。

## 设置预览与兼容

默认使用 `uiStyle: "simple"`、`theme: "system"`，宠物关闭。配置仍为 schema 1；新版本为缺失的 `uiStyle` 与宠物配置补充默认值，保留已有主题和窗口设置。旧 `personalization.background`、`personalization.effects` 只作为兼容输入忽略，不恢复背景或氛围功能。以前导入的图片留在原数据目录，当前版本既不读取也不删除。旧 `--import-wallpaper` 参数被拒绝，不能用启动参数恢复已移除的导入能力。

其他未知字段、无效枚举和宠物参数越界仍拒绝，不静默覆盖损坏设置。这里描述新版本读取旧配置的兼容，不承诺旧二进制支持新配置。

桌面设置草稿即时预览风格和配色，保存时只提交 `theme`、`uiStyle` 与 `closeToTray`，由 Rust 合并到最新设置；离开设置页恢复未保存的外观预览，真实设置读取失败时禁止保存默认草稿。角色选择立即保存，不等待「保存设置」。收到角色或宠物菜单更新后，设置页按旧设置、当前草稿和新设置进行三方合并：保留用户未保存的外观字段，宠物状态始终使用最新值，避免角色选择抹掉配色草稿，或外观保存覆盖宠物窗口的新偏好。

浏览器仅可在当前会话预览风格、配色与已装配角色的应用内模式，不能保存桌面配置、创建桌面窗口或使用系统托盘，刷新后清除。预览菜单只修改本地状态；桌面保存失败会明确显示错误，不把未完成操作当作成功。

## 宠物陪伴

当前有阿宝（`traveler-01`）和阿沐（`amu-01`）。阿宝由第一段棕发背包全身视频制作，保留完整站立—跑步—站立节奏；`loop.png` 为 768×768、97 帧、24 FPS、约 4.041667 秒的 RGBA APNG，`still.png` 为同画布静态形象。阿沐使用全身骑行视频 (3)，当前默认循环取连续源帧 51–130（含两端），共 80 帧、24 FPS、约 3.333333 秒；近景视频 (2) 弃用。

角色使用稳定 `id`，基础 `still` / `idle` 必需，其他动作只在实际有独立资源时显示。阿宝与阿沐原骑行 `loop.png` / `still.png` 保持不变；0.13.1 纠正托腮思考动作的背景透明性，0.14.0 只调整交互和状态管理，已有素材摘要不变。不重复用已有素材冒充其他动作，空目录和缺失模型保护继续保留。

App 内用角色卡选择阿宝、阿沐或「不启用宠物」，点击立即生效；再次点击同一角色可召回宠物。关闭宠物窗口或选择「暂时收起」只隐藏当前显示，可从托盘「显示宠物」或再次选择当前角色召回。主窗口收起到托盘不会自动结束桌面宠物，退出整个 App 时一起退出。透明窗口仍有矩形鼠标命中区域，不承诺按角色非透明像素穿透。

右键宠物打开统一 Vue 菜单面板：顶部显示当前头像、名称与播放状态，中间按显示位置、动作、大小和置顶分组，使用分段选择、按钮与开关，底部保留收起和打开 App。桌面使用 App 拥有的独立透明 `companion-menu` 窗口，基准 320×480 并按屏幕可用区域限制尺寸与位置，避免被宠物小窗口裁切；应用内使用同款页面面板，浏览器只预览本地状态，不提供桌面悬浮能力。失焦或 Escape 关闭菜单。0.14.0 的系统原生菜单属于历史实现，其结果不能替代当前面板验收。App 设置页不重复这些控制：

| 菜单项 | 行为 |
|---|---|
| 暂停动画 / 继续动画 | 更新唯一持久化播放开关 `animated`；系统减少动效时仍遵循系统偏好 |
| 显示位置 | 桌面悬浮或应用内陪伴；浏览器只支持应用内预览 |
| 动作模式 | 只列出该角色实际拥有的素材，选择后循环播放 |
| 大小 | 96、128、160、200、256 px |
| 始终置顶 | 仅桌面模式可调整 |
| 暂时收起 | 隐藏当前宠物，不停用角色或退出 App |
| 打开 OpenDesk | 唤起主界面 |

旧配置缺少 `actionMode` 时默认使用 `idle`。选择阿沐的「托腮思考」模式会在视频每次 `ended` 后重新播放；直接主点击阿沐则临时播放一次，结束后回到当前所选模式。动作选择、暂停状态与临时显示状态各自保留其含义，不以多份播放开关相互覆盖。

通用 `CompanionCatalog`、渲染、拖动与生命周期组件由组合根显式装配。已有两个 APNG 循环不变，阿沐完整骑行动作仍单独保留。思考动作现在保留人物与真实显示器、键盘、桌椅前景，去除房间背景和物体间的背景空隙；半身构图仍按原视频，不补画身体。

原默认素材来源仍由各角色目录中的 `SOURCES.md` / `provenance.json` 记录；透明思考动作的来源、参数和离线复现记录独立维护。2026-10-22 的发布授权不覆盖本次 0.15.0；原视频和声音不直接进入 App。0.13.0 不透明版本与 0.13.1 透明 WebM 的历史证据保留，媒体、Chrome 与原生启动证据分别记录，不互相替代。

`--smoke-test`、`--module-smoke`、`--companion-smoke` 仅在显式提供绝对路径 `OPENDESK_DATA_DIR` 时跳过单实例，可与用户实例并存；调用方负责选择不重叠的测试目录。变量缺失、空值、相对路径或重复/混用检查模式时，启动阶段退出 2；覆盖数据根不隔离全部 WebView2 缓存。宠物 smoke 校验当前所选角色的图片就绪与窗口生命周期，无资源或缺失模型不能冒充成功；实际本轮结果见验证记录。

## 阿沐思考动作的媒体与播放

0.13.0 的整幅房间已在 0.13.1 纠正为透明前景：正式 alpha VP9 WebM 为 768×768、145 帧、24 FPS，容器时长 6.042 秒，源帧节奏仍为 145/24 秒。固定取源区域 `[0,167,720,1280]`，缩放至 453×700 后放在画布 `(157,34)`，不逐帧重画或补身体。首帧生成 alpha 只辅助轮廓，颜色内容来自原视频；WebM 色彩转换不属于 RGBA 逐像素无损。

播放依赖媒体加载就绪与实际 `ended`，不以标称时长提前截断；每次主点击重触发从头播放，暂停、隐藏、减少动效及模型切换清理当前播放。0.14.0 将持续动作模式和临时主点击分开：前者循环，后者结束后回到当前模式。

0.13.1 的正式组件曾在可见 Chrome 黑、白、棋盘底使用真实 WebM 检查：5.902 秒时仍在思考，结束后回到当时的默认骑行，重播从约 1.968 秒回到 0.165 秒且使用新节点。当时完成原生核心 smoke 与正常启动，但未验收原生窗口新动作的实际点击和透明视觉。这些历史证据不替代 0.15.0 风格与菜单面板检查；当前验证状态见 [验证记录](verification.md)。最新公开版本仍为 0.12.0，本文不将源码或类型检查写成当前浏览器、构建或桌面视觉已经验收。

## 主界面右键菜单边界

主界面空白区域抑制浏览器默认右键菜单；输入框、可编辑区域和选中文字保留标准菜单。宠物区域使用自己的菜单。该策略只作用于宿主文档，模块 iframe 自身菜单未改，也不影响系统或其他应用的菜单。

## 模块内容区

模块外层使用主内容区剩余空间，宿主不围绕模块叠加重复标题和卡片边框。iframe 占满该区域，业务页面的纵向内容由 iframe 内 body 滚动；宿主不读取或测量业务 DOM 来驱动高度。加载、失败与关闭状态仍由宿主管理。

## 既有粉色配色调整

原版的画布、侧栏、边框、次级按钮与选中背景同时染粉，区域层次较弱；高饱和玫红又在柔灰画面中显得突出。调整为接近中性的暖灰画布、白色内容面板与更低饱和莓粉强调色；普通操作保持中性，导航选中增加边缘标记。原截图中发白的开关和保存按钮属于浏览器预览禁用态，不能当作正常态颜色不足的证据。

主题卡使用同一套颜色变量绘制侧栏、画布、面板与按钮的缩略预览，附带名称和配色说明。名称位于预览外，始终使用当前宿主的文字颜色；保存按钮放在设置页标题旁，避免新增选项后被推到页面底部。风格卡另外展示布局缩略图，帮助区分布局变化与配色变化。

## 颜色分工

| 主题 | 设计定位 |
|---|---|
| 樱花浅色 | 暖灰留白，低饱和莓粉用于操作和选中状态 |
| 海盐蓝 | 冷中性画布、蓝灰侧栏、深蓝主操作 |
| 松石绿 | 浅雾绿结构、深青绿强调；成功仍以文字和状态图标表达 |
| 暖砂岩 | 暖白面板、浅砂画布、棕铜强调；不与警告角色合并 |
| 石墨夜 | 中性石墨灰表面与浅青绿操作，区别于原蓝灰深色 |

`apps/framework/frontend/src/themes.css` 是颜色的单一来源，宿主、模块构建和缩略预览共用。主题只定义颜色，不在主题分支中改变布局或字体。`--border` 用于区域分隔，`--control-border` 用于控件边界，`--on-accent` 定义主按钮文字；成功、失败与未提交状态保留独立含义。侧栏焦点环使用适配侧栏的颜色，不直接沿用内容区焦点色。

2026-10-19 的历史配色检查记录了正常文字与按钮字关键色对达到4.5:1、焦点及控件边界关键色对达到3:1。这只覆盖当时选定的语义色对，不能替代当前七种布局的验证，也不代表完整可访问性审计。禁用控件、半透明装饰和第三方页签须按实际上下文另行检查。

## 兼容与扩展

SDK 的 `SUPPORTED_APPEARANCES` 管理配色，`SUPPORTED_UI_STYLES` 管理含 `mint` 的七种风格。protocol 1 的可选 `uiStyle` 缺失或未知时在对应 SDK 中回退为 `simple`；旧包可以忽略。基础 `theme` 始终保持 light/dark 兼容，graphite 使用 dark，既有 `nimdadesk:hello` / `nimdadesk:connect` 消息标识不变。共享 CSS 与 SDK 变更对应塔防 0.1.8、本地测试台 fixture 开发版本 1.0.7；公开范围仍只含塔防，测试台不公开。既有塔防 0.1.7 不覆盖，用户固定选择保留，需在「功能管理」手动选中已安装的 0.1.8 才能得到模块内部的薄荷样式。

`surfaceEffects` 继续保留协议兼容，但当前宿主只根据所选风格生成固定表面描述，没有用户材质、浓度或动效调节。深海透明使用静态深蓝黑半透明表面，其余使用对应静态样式；宿主不发送背景图片、路径、图片 ID、data URL 或宠物资源。SDK 对旧消息字段继续作有界解析，不能据此推断当前应用仍有背景与氛围功能。

宿主升级不自动替换用户已选模块包；已有用户在「功能管理」手动选择新版，旧包按自身实现呈现。风格、配色和模块公共表面样式纳入构建指纹，内容变化用新版本交付，不覆盖旧摘要。本文描述最终能力与兼容边界；0.8.0 的背景功能和运行证据保留在历史记录中，不改写成当前功能。实际测试、构建与运行结果见 [验证记录](verification.md)。
