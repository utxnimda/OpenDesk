# 虚拟伙伴

虚拟伙伴是 Windows x64 的独立页签，模块 ID 为 `virtual-partner`。当前源码版本为 0.8.2，沿用 hostApi 1 和 dataSchema 1。可以给伙伴取名、设置圆形头像、编辑性格，为不同 API 选择模型，也可以在记忆簿里翻看它从 B 站带回的见闻。[大肥鱼](https://github.com/SAKURAfan1023/dafeiyu-bot)提供了人格与独立记忆的交互参考。

## 使用

1. 在「功能管理」导入 `virtual-partner-0.8.2.ndpkg`，选择该版本并启用，再打开「虚拟伙伴」。搭配 OpenDesk 0.20.1 可以直接选择桌宠素材。已有伙伴沿用原有档案和自定义头像。
2. 不配置模型也可以改名字、调整性格、创建话题，或输入「记住：周末想画雨衣」。这个前缀触发本地保存，在记忆簿里可以查到来源并修改或忘记。也可以从用户消息或记忆簿手动添加。
3. 打开「伙伴设置 → 模型连接」，从 **当前 API** 下拉框切换已保存的配置，或点 **新增 API** 并填写名称、地址和 Key。OpenAI 的基础地址为 `https://api.openai.com/v1`。同一服务地址也可以分成两个账号，各自使用自己的 Key。
   在 **模型** 下拉框选择后保存。这份 API 会记住该模型；切回之前的 API 会恢复它自己的选择。想更换密钥时在对应配置里输入新 Key，沿用同一配置和地址时可以保留原 Key。新增配置或更换地址时须填写对应服务的 Key。
4. 发送消息时，Python 选取当前话题的近期对话和与问题相关的少量记忆，把它们连同角色设定交给所选服务。当次回答流式显示，停止操作会等待实际请求结束。切换话题或模型保留伙伴身份。页面配色随宿主设置。

模型下拉框优先显示该 API 的本地模型目录以及已选模型。没有缓存的已保存配置可在进入模型连接或切换 API 时读取目录；也可手动刷新。获取新目录调用服务商的 `GET /models`。该接口返回账户可见的模型 ID，伙伴聊天需要所选模型支持流式文本 Chat Completions。兼容服务没有提供目录时仍可手填模型 ID。[OpenAI 模型目录接口](https://developers.openai.com/api/reference/resources/models/methods/list)

## 让伙伴自己去 B 站逛逛

**聊天排版。** 伙伴的历史和流式回答均支持粗体、标题、列表、引用、表格、行内代码和代码块语法高亮。用户消息按原文显示。点击回复中的 HTTP(S) 链接会显示并选中地址，可以复制到浏览器。

1. 打开「虚拟伙伴 → 外出」。可选游戏、动画、音乐等兴趣，也可添加自己的词，最多八项。留空可以从热门尝鲜。点「外出一次」，修改了兴趣时按钮会显示「保存兴趣并外出一次」。
2. 伙伴从 B 站公开热门列表中挑一条没读过的视频，再单独读取详情。选择了兴趣但没有匹配的视频时，这一轮可以略过。在「外出见闻」展开来源，可核对视频链接、UP 主、标题和取得的简介。当前证据只覆盖文字资料。
3. 有模型连接时，伙伴可以为读到的条目拟一条留言，也可以选择不说。草稿显示在本地，可以复制后自行到对应视频下发表。若页签无法直接写入剪贴板，界面会选中草稿供你按 Ctrl+C；展开来源也可以点选视频地址。没有模型或拟稿失败时，读到的内容仍会保留。回到聊天问“你最近在 B 站读了什么？”，回答下方可以查看引用的外出记录。
4. 想让伙伴自己决定何时出门，在同一页勾选「允许伙伴自动外出」，先保存想用的兴趣。首次最早在一分钟后尝试。虚拟伙伴页签可见时才开始新一轮；自动尝试至少间隔 60 分钟，按本机日期每天最多三次。休眠或关闭期间错过的轮次不会补跑一串，取消勾选会停止安排下一次。

**外出记忆。** 在「记忆簿 → 外出经历」查看伙伴读过的内容，0.7.0 保存的记录也会直接出现。标题、作者、简介、来源、草稿和对来评的回复按同一条经历归档。较早的记录可以翻页；点聊天中的来源可以查看当时引用的经历。忘记某条经历会移除其详情和拟稿，并停止在后续对话中引用；保留已见视频标识用于去重。

**回应来评。** 在「外出 → 外出见闻」展开某条视频的「针对一条来评拟回复」，粘贴对方原话并点「拟一条回复」。每条见闻可记录十条来评。模型可以拟一条回复或略过，界面会区分手动提供的原话与未发布的草稿。

**B 站自动评论和收件箱自动回复已暂缓。** 本版外出只读取公开视频资料。你可以手动粘贴来评，复制伙伴拟好的留言或回复，自行到 B 站发表。草稿与来源保存在「外出经历」。重新评估自动发送前，需要核实平台提供的渠道、账号权限及发送回执。[B 站开放平台文档](https://open.bilibili.com/doc) · [未列出的接口能力](https://open.bilibili.com/doc/4/c381daac-4b6d-9ed3-3604-19a78d358eec)

## 本地 API 配置

伙伴模块数据目录里的 `connections.json` 保存 `schemaVersion: 2`、当前配置 ID（`activeId`）以及配置数组（`profiles`）。每项有独立的 `id`、`name`、`baseUrl`、已选 `model`、模型目录 `models` 和密钥引用 `credentialRef`。目录为 `null` 表示尚未读取，空数组表示服务返回了空列表。Key 位于同目录下的 `credentials/*.dpapi` 文件中，使用当前 Windows 用户的 DPAPI 加密。设置界面可以替换密钥，只回显保存状态。

首次读取新版配置时会导入旧 `connection.json` 的地址与模型，为原 Key 建立新版专用的加密引用。旧版单连接文件保留给旧包使用；此后新版以数组文件为准，二者的编辑各自独立。修改 API 或模型只影响后续模型请求，不修改伙伴的人格、话题或记忆。

## 伙伴名字和头像

在「伙伴设置 → 角色设定」中编辑名字，点「保存设定」或在名字输入框中按回车。保存成功后聊天页同步显示新名字，重新打开仍能读到同一份档案。0.4.1 修复了旧版点击保存时被宿主 iframe 阻止原生表单提交的问题。保存直接走页签 RPC，保留已有的字段校验。

在同一处设置头像，聊天页顶部、欢迎区、设置预览及取景框都以圆形显示：

- **使用当前桌宠。** 没有保存自定义头像时，自动显示当前启用桌宠的待机动画首帧。读取失败时尝试该桌宠的静态图，没有启用桌宠时显示名字首字。切换桌宠会更新默认头像，不写入伙伴档案。
- **从桌宠选择。** 选择已登记的角色和形象／动作，用帧滑块或「上一帧」「下一帧」挑出画面。即使当前桌宠关闭，也可以手动选取已登记的阿宝或阿沐。固定选取不改变桌宠窗口的动作或当前角色。
- **选择本地图片。** 支持 PNG、JPEG、GIF、APNG 和 WebP，文件上限为 8 MiB。具有多帧的图片可以按实际帧选取。没有桌宠头像接口的旧宿主仍可使用本地图像编辑。
- **取景并保存。** 放大或缩小取景比例，拖动图片（也可在取景框内按方向键）确定圆框里保留的部分。点「保存设定」后保存为固定头像，之后切换桌宠仍保留这张图。点「恢复默认头像」并保存，重新跟随当前桌宠。再次裁剪已保存头像时使用已保存的小图，想取原图的其他区域请重新选择原素材。

自定义头像以 96 × 96 的 RGBA 像素保存在伙伴本机档案中，保留透明区域。圆框只用于展示。原图路径、源动画、文件名和拍摄信息不会随档案保存。模型请求仍只使用文本资料。

## 试用 0.2.0

- **教伙伴怎么说话。** 在「伙伴设置」的角色设定里添加一组对话示例，例如用户说“我刚画完第一张草图”，伙伴答“想让我先看构图，还是先听你讲讲它？”最多可保存三组，也可以全部移除。示例随人格用于之后的回答，聊天历史里不会出现虚构的示例回合。
- **选择值得留下的偏好。** 在普通聊天里说“我喜欢用铅笔起稿”。这次回答成功完成后，消息旁可出现一条本地记忆建议。点确认后才能作为跨话题的记忆使用；可以忽略，也可以在记忆簿修正或忘记。判断使用有限的本地表达规则，提出建议不会多发一次模型请求。
- **分享一条近况。** 打开近况并选「分享给伙伴」，填标题、可选的原文摘录、来源链接和自己的感想。也可以只保存标题。条目显示“用户分享”和证据类型，链接作为本地出处保留，页签不自动打开链接。询问相关主题或近期分享时，回答可显示参考了哪些条目。修改或移除会让旧版本的引用失效。

本轮只在该伙伴的私聊范围使用分享。模型请求只包含相关条目的标题、证据类型、用户提供的摘录和备注；链接、记录 ID 与整本近况簿不随请求发送。待确认的偏好仍属于原话题的聊天记录，只有确认后的记忆才进入跨话题检索。

## 所有权与展示

宿主提供当前模块专属的数据根。角色、话题、消息、记忆及来源由该目录中的 SQLite 保存，模型连接在同目录保存配置，凭据使用独立命名空间的 Windows DPAPI 保护。每条记忆可显式修正或忘记。历史聊天保留供用户阅读，旧事实在修正或忘记之后不再通过之前的话题上下文被自动重放。记忆库只选取本轮相关的内容发送给配置的服务，不读取其他页签会话或工作区。

角色档案拥有持久的 `persona.id`，改名、切换模型或更换头像时仍指向同一个伙伴。0.6.0 在独立聊天页按需读取宿主提供的桌宠头像帧。形象资源和窗口生命周期继续由宿主宠物功能拥有，档案、凭据和记忆归伙伴模块。通过桌宠窗口发起对话仍属后续能力。

## 开发

后续开发按[虚拟伙伴开发手册](virtual-partner-development.md)执行。手册以 OpenAI API 为文本模型基线，列出基线验收、第一轮工单及后续网站、群聊、语音和直播的接入顺序。

源码位于 `apps/features/virtual_partner`。入口清单显式列出档案、连接、话题、记忆、对话和外出的 RPC 方法。模型调用在后台线程中执行，前端通过短 RPC 读取进度。对话由用户发起；外出拟稿由单次外出或已开启的自动外出触发。浏览及草稿与私聊使用独立的输入范围。

```powershell
npm run test:partner
npm run build:module -- virtual-partner
```

构建命令将 0.8.2 包输出到 `dist/modules/virtual-partner/0.8.2/`。各本地开发包保留在原版本目录中。App 默认只随附塔防，虚拟伙伴单独分发。公开版本见[下载索引](downloads.md)。
