## 阿沐托腮思考：透明纠错

用户视频 (4) 是现有阿沐的新动作，`thinking` 不创建新角色。用户接受半身并要求保留电脑桌前景，但在看到 0.13.0 后明确指出，整幅房间画面不符合预期，应像骑行动作一样让背景透明。

0.13.1 的保留范围是阿沐、显示器、键盘与桌椅等真实前景；去除墙面、天花板及物体之间的房间空隙，不补造原片没有的身体。阿宝与阿沐已有 `loop.png` / `still.png` 保持不变，也不恢复已移除的 App 背景与氛围功能。

### 历史实现与正式透明资源

0.13.0 使用静音 H.264 MP4 重封装保留整个房间，并另导出只有外围透明边距的 APNG。这些记录说明当时制作和播放了什么，不证明人物与房间已分离；旧版本构建、视频原帧一致性与播放验证不能充当 0.13.1 的透明验证。

正式生产 `apps/features/companion/assets/amu-01/thinking.webm` 为 14,061,447 字节，SHA-256 `9a0d6c9cf31a40458ed4d15d62557ed4da841042df705da1dfada3e8b3812449`。资源为 768×768 alpha VP9、145 帧、24 FPS；源动作时长为 145/24 秒，容器时长为 6.042 秒。固定源裁剪 `[0,167,720,1280]`，缩放 453×700，画布放置起点 `(157,34)`，不逐帧移动画布。

首帧生成的 alpha 只作为轮廓参考，逐帧遮罩由 OpenCV 媒体流程处理；最终颜色帧基于原视频采样，不将生成图当作视频帧或重画人物。透明 WebM 需要重新编码，VP9/YUV420 色彩空间转换可能带来色差，因此不宣称 RGB 逐像素无损；保留原帧序和节奏也不等同于保持编码前后的所有颜色字节。

0.13.1 强制 VP9 解码后，全部 145 帧的 alpha 0/255 区域保持，中间 alpha 最大差为 1。该版正式 WebM 在可见 Chrome 的黑、白、棋盘底用正式组件检查，房间背景与物体间背景透出；5.902 秒仍在思考、结束后回到当时的默认骑行，重复触发从约 1.968 秒回到 0.165 秒并换新节点。本机证据为 `.local/amu-thinking-alpha-real/result.json` 及其引用文件。这些是正式素材结果，不沿用合成样片作为证明；当时未验收原生新动作点击/透明视觉。

0.13.1 完成 234 项自动化检查、Tauri/NSIS 构建和原生核心 smoke。固定 `dist/OpenDesk/OpenDesk.exe` 的该版正常启动记录为 `.local/transparent-launch-20261023-114055/verification.json`：版本 0.13.1，阿沐桌面模式及既有风格/配色、其他偏好和模块选择保留，`frontend.ready` / `companion.ready` 到达且错误数为 0。启动就绪不能替代原生新动作的点击和透明视觉验收；这些历史结果也不是 0.15.0 的完整检查或构建结论。当前验收分别见 [验证记录](verification.md)。

## 已读取的会话

来源：[制作视频人物桌面宠物](codex://threads/019fad05-d95a-7d32-a8b7-8925f90f76ab)。已读取该会话中与图片、视频、逐帧动画、透明边缘和角色独立配置有关的上下文。该会话使用独立 Pet 工程；本轮没有修改它，也没有复制其中的角色或声音资源。

可以沿用的制作要求：

- 动作应有逐帧的肢体和姿势变化。参考会话明确要求跑步、散步、睡觉等真实动画，不能把整张静态图的平移或摇摆当作角色动作。
- 角色先有一致的形象基准，再生成各个动作；发型、衣服、配色、比例、画面尺度及脚底基线需保持稳定。
- 桌面显示采用带透明 alpha 的 PNG/APNG 等资源；保留静态形象供暂停、隐藏或系统减少动态效果时使用。
- 参考工程处理过 48 帧、约 12 FPS、3984ms 的循环 APNG，也处理过 8 帧动作表；这些是历史实例，不是所有新动作必须采用的参数。
- 边缘验收应检查锯齿、杂点、内部小孔、背景色污染及缩放后的轮廓。参考会话后来使用 768×768 输出并在 150% DPI 下检查；OpenDesk 应结合实际 96–256 px 展示尺寸验证。
- 各角色的声音与其他配置应独立。新角色没有自己的已授权语音时保持静音，不继承旧角色的声音、模型 ID 或直播配置。本次重建不接入声音或直播功能。

## OpenDesk 当前资源接口

组合根通过 `CompanionCatalog` 显式提供角色，框架不直接导入具体角色文件。无资源时使用 `defaultId: null` 和空 `models`，并禁用依赖资源的显示操作。

每个模型需要稳定的 `id`、显示名称、说明，以及最少两项资源；其余动作按实际提供的素材选配：

| 字段 | 用途 |
|---|---|
| `still`（必需） | 静态形象、暂停或减少动效时显示 |
| `idle`（必需） | 默认播放的角色循环；本次对应用户提供的视频动作 |
| `walk`（可选） | 额外活动状态，仅有独立资源时显示入口 |
| `wave`（可选） | 点击互动/挥手；实际为静态资源时应如实说明 |
| `sleep`（可选） | 休息状态；实际为静态资源时应如实说明 |
| `thinking`（可选） | 阿沐托腮思考，保留人物与电脑设备前景、背景透明；可选为循环模式，也可主点击临时播放一次 |

组合根的 `assets.thinking` 已指向正式 `thinking.webm`，并保留 `actionMediaTypes.thinking: "video"`、`actionDurationsMs.thinking: 6042` 和 `primaryAction: "thinking"`。持久化 `actionMode` 决定持续模式，缺失时按 `idle` 兼容；菜单只提供角色实际具备的动作。所选思考模式在视频 `ended` 后开始下一轮。主点击 `primaryAction` 临时播放一次，完成后回到当前所选模式；重复点击换新播放代次和视频实例，从头播放。视频加载就绪后才播放，6042 ms 不用作提前结束计时。暂停、隐藏、减少动效、模型切换及卸载清理播放。透明 `thinking-still.png` 不替换原骑行 `assets.still`。

`animated` 是唯一持久化播放开关，临时隐藏与播放代次不作为第二份开关保存。App 设置只提供角色卡与停用选项，选择立即写入，重复选择当前角色会召回；托盘也可显示已收起的宠物。显示位置、实际动作模式、96/128/160/200/256 px 大小、桌面置顶、暂停/继续、暂时收起与打开 OpenDesk 归属宠物菜单，功能不因本次面板重做而扩大。

当前 `CompanionMenuPanel` 共用头像与名称、状态、分组、分段选择、大小按钮、置顶开关和底部操作。桌面由同进程拥有的透明 `companion-menu` 窗口承载，基准 320×480 并限制在屏幕可用区域内，避免小宠物窗口裁切；应用内使用同款 DOM 面板，浏览器只作本地预览。失焦或 Escape 关闭，菜单代次用于拒绝已经关闭、被替换或角色变化后的迟到更新。0.14.0 的 Tauri 系统原生菜单是历史实现，不能描述成当前仍使用，也不提供当前面板的视觉验收证据。

宠物和菜单窗口只拥有各自受控入口。菜单读取必要设置与宠物上下文，仅可提交有界单字段偏好、隐藏宠物、打开 App、关闭自身并报告就绪；不含任意 shell、业务 worker、完整设置写入或角色选择权限。Rust 持有权威设置并检查窗口、参数与代次后合并单项变更；主界面外观保存只写配色、风格和关闭到托盘偏好，不覆盖宠物菜单的最新状态。通用框架管理菜单、媒体和生命周期，仍由组合根提供实际角色与资源。

阿宝仍使用原有 `idle` 循环与 `still`；阿沐也保留原骑行循环和静态图，本地 0.13.1 纠正独立 `thinking` 托腮思考动作的背景透明性。只有实际存在的额外素材才显示入口，不重复映射原循环冒充新动作。该动作保留真实电脑设备前景并去除房间背景，不能再把完整房间矩形当作透明角色。

## 收到参考视频后的顺序

1. 记录用户提供的参考视频及允许使用、分发的范围，不沿用已撤下素材的授权假设。
2. 核对用户视频中的现有角色、全身构图、动作区间、源帧率与循环要求；偏好尚未明确时说明可逆默认选择。
3. 对现有视频按原帧进行透明化与固定画布处理，记录工具和参数；没有额外授权时不 AI 重画、不插帧、不变速，也不从缺失部位生成身体。
4. 将逐帧素材按确定的时序制作成适合桌面播放的文件，检查透明度、身份一致性、边缘和循环接缝；如尚无真实动画，不标注为已完成动画。
5. 记录最终文件的尺寸、帧数、时长、SHA-256 和来源，再通过组合根注册；验证应用内和桌面两种模式、暂停、隐藏与退出。
