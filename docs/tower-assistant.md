# 塔防山贼助手

本模块是 OpenDesk 的一个内置业务模块，包含「灵物总览」「渡劫布局」与「工作与战斗」。前端位于 `apps/features/tower_assistant/frontend`，存档读取、规划、采集管理与统计位于同模块的 `backend`，固定原创观察脚本位于 `capture`，由应用组合层注册。没有迁入以前独立规划器或自动搬迁助手的代码。

**正式交付（2026-10-29）**：[塔防助手 0.9.3](https://github.com/utxnimda/OpenDesk/releases/tag/modules%2Ftower-assistant%2Fv0.9.3) 与 [App 0.19.3](https://github.com/utxnimda/OpenDesk/releases/tag/v0.19.3) 从干净提交 `92c22f21d21f5287e8acb515d1de4509ed1bec50` 构建；App 仅随附塔防 0.9.3，独立页签与随附包字节一致。[AI 工作台 0.4.4](https://github.com/utxnimda/OpenDesk/releases/tag/modules%2Fai-workbench%2Fv0.4.4) 同轮独立发布，三个 Release 的 14 个附件均已重新下载并核对 SHA-256。本次附件不含测试包、部署工作台、作品管理器附件或本机数据，历史公开版本和本地开发包保留。

0.9.3 同步新版宿主公共外观，并提供经宿主明确授权的只读统计摘要 `tower.ai.summary`。AI 的 API 会话只能读取已打开塔防实例的当前摘要，不会因此启动采集、打开任意路径或修改游戏文件；该工具能力需要 0.19.0 或更新宿主，推荐使用 0.19.3。升级 App 不自动切换用户固定的塔防版本；已有用户需在「功能管理」导入并选择 0.9.3。原有存档分析、工作／战斗统计和透明排行功能继续保留。

历史 0.8.2 与当时已完成本地限定范围验证的 0.8.1 功能一致，保留主页面紧凑表格、透明窗游戏条形榜、工作分类多榜、伤害属性/职业筛选和历史明细公式快照修复。0.8.2 已完成独立的干净构建、冻结包 RPC 和产物审计；既有 0.8.1 dirty 包及历史验证结果保留，不能改写成其他版本的构建证据。本次发布不改变便携配置、个人选择、`runtime` 数据、游戏文件或存档。

0.7.0 的透明统计排行榜已完成构建、自动化和通用原生窗口链路验证，游戏上的透明叠加视觉尚未验收；这些结果不代替 0.7.1 的验证。此前 **0.6.1** 保留为已完成限定范围本地验收的不可变包。模块从 Git 主线的 0.1.9 继续开发，保留 0.4.0 候选的灵物总览能力，没有恢复或合并本机 0.3.0。稳定功能 ID 沿用 `tower.spirit-inventory`（灵物总览）、`tower.output-statistics`（采集与计时统计）、`tower.damage-explanation`（逐击公式与局部敏感度）、`tower.work-explanation`（实际工作公式与取整步骤）和 `tower.statistics-overlay`（透明统计排行榜）；已有 `tower.save-reader`、`tower.map-details`、`tower.tribulation-plan` 保持含义，不改写宿主历史记录或既有验证结论。

## 输入与操作

1. 在游戏中正常保存，打开工具台侧栏的「塔防山贼助手」。
2. 选择包含 `package.nw` 的游戏安装目录，读取存档。默认最近一次保存，也可选择其他存档。
3. 默认进入「灵物总览」，查看已摆放和仓库的全部灵物，按基础灵气降序比较。同值并列（例如 1、2、2、4），位置筛选和名称/编号搜索保留全局名次。
4. 点击排行中的已摆灵物定位地图；点击地图中的灵物反选排行。详情分别展示基础灵气、当前置物台加成后的灵气、对所选渡劫台的贡献及五行。仓库灵物显示「未摆放」，不会伪造当前贡献。
5. 在「渡劫布局」中选择渡劫台并生成方案。渡劫台当前位置保持不变。查看前后对比地图、编号清单并导出 SVG；原有人物/建筑详情与同格对象切换继续保留。

地图及仓库信息来自标明时间和摘要的那一份存档，不是游戏实时状态。这两个存档视图不写存档、不启动或控制游戏、不发送搬迁指令。导出的图用于人工执行建议。

基础灵气取自灵物本身，不能用五行之和替代。置物台灵气按照游戏运算顺序计算：`Math.round(10 × 基础灵气 × (1 + 台等级 × 0.15)) / 10`；只在与渡劫台的曼哈顿距离不超过 3 时计入其贡献。排名采用基础灵气，使仓库与已摆灵物可以直接比较；当前加成和范围贡献只作为独立详情。读取器同时支持经整组规则摘要核验的 2026-10-18、2026-10-25 与同日 r2 游戏包，后两者为 23 层存档数组；未知或混合版本拒绝解析。

## 工作与战斗采集

0.5.1 的 Blob Worker 入口会破坏游戏相对资源加载基准，真实启动可能黑屏，已停止将其作为可用采集版本推荐。0.5.2 改用包根固定文件 `opendesk-capture-worker.js`，与原 `workermain.js` 同目录，再加载原引擎，保留资源解析基准；观察脚本失败时报告错误并继续启动原游戏。当时已通过退出游戏、移除恢复并安装 0.5.2 修复入口处理旧黑屏问题。当前版本保留该入口布局；仅更新页签不会自动改写已经安装在游戏内的旧脚本。

当前源码已实现采集安装/恢复、后台统计、命名 RPC 和「工作与战斗」界面。统计依赖实际观察到的游戏事件，不能从存档差分、物品产量或游戏已有的战斗累计值推导完整输出。采集入口支持整组摘要已核验的 `audited-2026-10-25` 与 `audited-2026-10-25-r2` 游戏包；存档读取支持旧版本，不表示旧版本也能安装采集入口。版本范围以完整规则摘要为准；游戏更新后的新包即使名称与存档层数相同，也必须重新核验，不能据模块版本认定本机当前游戏受支持。

1. 填写包含 `game.exe` 和 `package.nw` 的游戏安装目录；目录为空时会展开输入并提示先填写。安装状态与进程状态分别检查，无结果或读取失败时保持未知，不显示为未安装/未运行。主菜单阶段即可检测进程与已安装入口，不要求载入存档。仅当明确显示未安装时，先在游戏中保存并手动退出，再点击「安装采集入口（需重启游戏）」。界面会直接说明修改范围，运行中的游戏不能直接附加。
2. 安装器核对同路径 `game.exe` 进程已退出、ZIP 结构与完整规则版本，备份原 `package.nw`，记录原包/安装后包的 SHA-256，再加入固定 `inject.js`、`observer.js`、根级 `opendesk-capture-worker.js` 和 `inject_js_start` 入口。已有其他注入配置、路径重定向或无法核实的进程都会拒绝安装。
3. 手动重新启动游戏并进入存档，等待采集状态显示已连接后点击「开始计时（新会话清零）」。从当前流序号之后开始记录，不把开始前的缓存事件计入本轮。
4. 主页面工作榜每个工作类型一张紧凑表格，横向排满后自动换行，分别查看最近实际量、次数和累计。战斗可合并选中伤害属性，也可按属性或职业拆成多个榜，展示人物头像、完整伤害、每真实秒伤害及占比。点击工作榜的最近单次或攻击最近条目，会读取并固定该组在后台处理请求时最近一次事件的公式；点击逐次明细仍读取指定序号，点击人物头像查看人物快照。详情固定保留至手动关闭，轮询、筛选和新会话不会自动关闭；停止后仍可查看本轮结果，再次开始生成新的会话 ID 并清零。
5. 移除时先停止计时并手动退出游戏，再点击「移除采集入口并恢复原包」。当前包必须仍匹配安装后的摘要，备份必须匹配原始摘要；游戏更新、备份损坏或文件在操作期间改变时拒绝覆盖。恢复后保留备份及安装记录，删除采集配置和事件流。

已安装时可展开「采集入口管理」查看说明与安装/移除操作。状态检查将已安装的三个脚本与当前包比较；`updateRequired: true` 表示入口需更新，`null` 表示尚无法确认。出现更新提示后，先停止计时并退出游戏，移除入口恢复原包，再安装新入口并重启游戏。旧入口仍可统计其已有字段，新增工作细分、公式、人物资料和攻击分类缺失时保持未知，不推测补齐。

备份、身份令牌与事件流位于游戏目录的 `.opendesk-capture`，均为本机数据。安装会修改游戏包，但不修改存档；观察脚本保留原游戏调用的参数、接收者、返回值和异常，不设置游戏数值，也不为取得快照再次执行游戏公式。工具不会启动或关闭游戏，也不提供任意注入脚本、网络监听或远程上传入口。

### 工作输出范围

当前观察 **9 个消费动作边界**，不是 9 个独立界面类别：

| 消费边界 | 数量 | 列表类别 |
|---|---:|---|
| 伐木、采矿、种植对应的资源消费 | 3 | 伐木 / 采矿 / 种植 |
| 研究 | 1 | 研究 |
| 操练 | 1 | 操练 |
| 锻造/工艺共用消费 | 1 | 锻造 / 工艺 |
| 炼丹 | 1 | 炼丹 |
| 建造 | 1 | 建造 |
| 城墙修复最终消费 | 1 | 城墙修复 |

每次取 `采集核心碰撞` 的完整工作量参数，修墙只在最终消费处计一次，不因中间重复赋值重复累计。一次输出 100 万而任务仅剩 1 万，实际工作量仍计 **100 万**。工作类型来自当时实际执行状态；旧入口未细分的「采集」「锻造与工艺」继续保留原类别。每个已选工作类型独立排行，只列有该工作记录的人物；显示最近一次实际工作量、工作次数和完整累计，最近一次乘次数不能代替累计。未覆盖的消费分支不冒充已统计。

新入口记录实际工作表达式的原始输入、固定增加量与返回结果。已核验的四个分支在 `audited-2026-10-25` 中为 `5615–5618`，在 r2 中为 `5620–5623`；普通工作使用 10 项输入，城墙修复使用 11 项。点击工作条目可查看公式、原始项、取整步骤及复算是否匹配本次实际输出。普通工作先对增产乘积向上取整，再加固定增加量的向下取整；修墙将最终增产放在加算区，内层取整后乘修墙倍率、加固定项，最后再次向上取整，不能套用普通工作顺序。完整规则见[采集规则](tower-game-rules.md#工作与伤害采集规则)。没有公式的旧事件仍保留实际量和次数，并说明公式不可用。

### 伤害与公式范围

已核实的人物伤害在扣血前保留完整返回值，界面主指标只展示完整伤害与 DPS（每真实秒伤害），不以目标剩余生命截断输出。只有可确认人物和命中归属的已映射动作进入统计，不把其他伤害来源混入人物输出。

人物榜显示头像、职业、完整伤害、DPS 和占比。力（物理）、智（魔法）、敏（穿刺）及「其他/未知」可多选，以选中范围合并排行，或按选中的属性、人物职业分别排行；不再把三种属性作为同一表的三列。攻击明细独立按普攻、技能、持续伤害及未知类别分组，显示命中次数、平均每次及最近一次伤害，不据伤害属性筛选伪造属性与攻击类别的交叉统计。当前观察器没有可靠的施放 ID，多段或多目标技能可能产生多次命中，因此不把命中次数称为施放次数，也不从命中数推算释放次数。人物资料来自实际事件中的职业、外观、当时工作、可取得的属性和装备快照；头像使用同一游戏包的图标。点击人物查看的是标明事件序号的快照，不读取存档冒充当前资料。

主伤害表达式在两个采集版本中分别为 `5579`、`5584`，经逐字核对计算正文与输入顺序一致；根据实际规则版本选择，保留以下 **14 项**原始输入：面板攻击、技能系数、本次暴击系数、普技增伤、攻类增伤、元素增伤、敌类增伤、护甲增伤、目标防御率、护甲克制倍率、五行克制倍率、最终增伤倍率、职业类型倍率、技能元素倍率。Python 按游戏的浮点运算顺序复算：

```text
向下取整[面板攻击 × 技能系数 × 本次暴击系数
  × (1 + 普技增伤 + 攻类增伤 + 元素增伤 + 敌类增伤 + 护甲增伤)
  × (1 − 目标防御率) × 护甲克制倍率 × 五行克制倍率
  × 最终增伤倍率 × 职业类型倍率 × 技能元素倍率]
```

仅当复算值、表达式原结果和完整伤害一致时提供局部敏感度：逐次只改变一个输入，乘区提高当前值的 1%，加算增伤提高 1 个百分点，目标防御率降低 1 个百分点，再取整并按本击增加输出排序。界面展示每行改变幅度、调整后输出、增量和百分比；各项投入成本不同，不是同成本装备排名，也不包含攻速、冷却、暴击概率、持续输出或后续目标状态变化。复算不一致保留原值并停用收益比较，前端不复制计算公式。

公式覆盖分为 `main-product`（上述主公式）、`special-return`（特殊返回值）、`stored-buff-value-only`（已存储的持续伤害值）和 `unavailable`。特殊返回/击杀分支尚无独立公式；持续伤害只记录本次消耗的存储值及有效伤害，没有采集最初生成该值的公式；其他未核验分支不套用主公式。伤害数值可被记录不等于其来源公式已经完整解释。

### 容量、时序与失败处理

| 实现边界 | 当前行为 |
|---|---|
| 滚动统计明细 | 最多 **500 条 / 256 KiB**，容量先到者生效；更早事件仍在本轮累计中 |
| 每组最近事件 | 独立保留最多 **512 组 / 2 MiB**；工作按人物与工作类型、伤害按人物与攻击类别/技能区分，供汇总格请求最近公式；完全淘汰后明确提示不可读取 |
| 汇总分组与人物 | 原汇总最多 **512 组**，人物最多 **512 人**，工作/伤害展示分组最多 **1024 组**；超出时中断，不静默丢弃累计 |
| 人物资料 | 单人快照最多 **4 KiB**，全部人物快照合计 **256 KiB**；逐次明细的校验载荷保留事件当时资料，公式详情解出该事件的完整人物快照 |
| 采集环形记录 | 最多 **1000 条**，同时受 **2 MiB** 流文件限制，单条最多 64 KiB；容量先到者生效 |
| 心跳 | 游戏观察器每 **1 秒**发送；超过 **5 秒**未更新或时钟异常，流不再视为连接有效 |
| 游戏端写入 | 每 **250 ms**尝试异步、串行地原子替换流文件；Windows 短暂占用最多重试 150 ms，不先删除旧完整文件 |
| 后台读取 | 统计运行期间由 worker 每 **200 ms**读取；与前端是否打开统计页独立 |
| 页面刷新 | 每 **1 秒**串行请求一次快照；请求耗时期间不重叠，实际间隔随操作耗时延长 |

这些是调度与容量边界，不是端到端延迟或每秒吞吐保证。环形记录正常淘汰旧条目不等于采集失败；如果 worker 落后到越过所需序号，则按断档中断。消息身份错误、观察失败、显式丢失、重复/乱序/回退、游戏会话改变、非法数值、包变动及心跳失效都不能继续伪装成完整连续统计。

统计使用真实经过时间，包含游戏暂停期间；明细另含流序号、可取得的游戏时间和计时后收到时间。排行榜随选定指标更新顺序，同值用人物编号稳定排序；行与榜使用稳定身份，已打开详情不依赖排行位置。选择明细会固定该条目并暂停列表显示，汇总、后台计时与采集继续；恢复显示后重新显示最新明细。固定详情使用独立副本，已经打开的内容不会因轮询、明细淘汰、切换工作/战斗或新会话消失；读取失败也保留面板和原因，由用户手动关闭。

0.7.1 将汇总条目的「最近一次」与历史明细分开读取：工作按人物与工作类型、攻击按人物与攻击类别/技能定位，并携带当前会话 ID；后台在同一锁内读取事件并生成公式快照，返回的是后台处理请求时最近一次事件，可能晚于界面上一轮显示的序号。读取成功后固定返回的事件及其序号，后续重读不会自动跳到更新事件。

0.8.1 为已显示的逐次明细附带 `detailSnapshot`，包括 worker 生成的原始 JSON 载荷及完整性签名。载荷绑定原会话、原序号、公式输入和当时人物资料，前端只保存与传回，不复算业务公式。点击或重新打开冻结列表中的事件时，worker 校验后复算这条原事件，不依赖滚动缓存是否仍保留它，也不会改读同组最新事件。在同一 worker 的目录统计实例仍保留时，开启新计时也能查看已取得的旧会话快照；worker 重启、换包或该目录实例被容量淘汰后明确拒绝，不能凭空恢复旧数据。缺少快照的旧序号接口仍严格依赖原会话与后台保留事件；缺少公式的采集事件仍如实提示未采集，不由快照补造公式。

数字显示可选「完整数字」或「中文单位 · 4位有效数字」。0.7.1 的完整模式将工作量、伤害、DPS、平均单次及输出增量等四舍五入显示为整数；中文单位模式仍按千、万、亿、兆、京缩写，极大或极小值使用科学记数法。这些格式只影响显示，不改变后台精度、累计、次数、排名或公式计算；详情中的公式原始项、倍率保留精度，属性、时间、公式步骤和百分比也不套用输出整数格式。切换页签只停止前端轮询，后台继续；界面断线保留上次成功结果并明确状态待确认，不自行推进计时。累计由 worker 内存持有，worker 退出后不持久保存；运行中不允许切换游戏目录。

### 多榜排行与透明窗口（0.8.0）

「工作与战斗」中的「透明排行榜」从塔防助手 **0.7.0** 起提供，需要 **OpenDesk 0.18.0 宿主**，正式 0.8.2 沿用此要求。仅导入新页签不能给 0.17.0 宿主增加原生窗口能力；旧宿主仍可使用页签基本功能，点击该入口会显示「需升级宿主以支持透明窗口」。App 0.18.0 与页签 0.8.2 分别下载安装和选择，发布不自动改写个人选择。通用原生窗口链路已通过，游戏上的透明视觉效果尚未验收。

0.8.0 按用户确认的组合提供主页面紧凑表格与透明窗游戏条形榜。两处共享从 worker 汇总生成榜单的只读展示逻辑，工作榜按类型、战斗榜按属性或职业横向排满后换行；窄窗口自动成为单列。透明窗行背景条形以同榜最大累计量为满格，百分比仍表示该人物占整榜累计量的份额，两者含义不同。

窗口读取主面板同一 worker 的统计快照。计时开始/停止及采集管理留在主面板，打开或关闭排行榜不会新建、清空或停止计时会话；主模块关闭、停用或切换包时，宿主撤销并关闭对应窗口。初始工作/战斗分类、数字模式、游戏目录及排行筛选来自打开时的主面板，打开后两边筛选各自独立。筛选上下文按字段、枚举、数组长度和完整 JSON 8 KiB 上限校验；非法上下文显示错误，不静默展示为其他筛选结果。窗口内筛选仅改变展示，不写入累计。

| 选项 | 当前口径 |
|---|---|
| 工作/战斗 | 工作类型多选，每种工作一榜；战斗支持选中属性合并、按属性分榜或按职业分榜 |
| 人物与职业 | 搜索人物名称或编号；职业可多选已采集职业或未知；全选包含后续新类别，清空明确表示不选任何类别 |
| 战斗输出口径 | 力/物理、智/魔法、敏/穿刺、其他/未知可多选；透明窗另保留普攻、技能、持续伤害、未分类攻击口径，与属性筛选互斥，不提供无法从现有数据确认的交叉统计 |
| 排序 | 主页面：工作可按累计量、最近单次、工作次数排序，战斗可按累计伤害、DPS 排序；透明窗另支持平均单次，以及战斗命中次数、最近单次。工作不展示或使用 DPS，工作次数与战斗命中次数分别标注 |
| 显示人数 | Top 5、Top 10、Top 20 或全部；可隐藏零输出人物 |
| 数字 | 完整数字或中文单位四位有效数字，沿用主面板的显示规则 |

排行和占比根据全部符合筛选的后台汇总计算，再截取 Top N；分母不会随可见人数变小。DPS 使用同一计时会话的真实经过时间，平均单次为所选口径的累计量除以工作次数或命中次数。未知分类保持未知，不把命中次数当作技能施放次数。点击人物会固定该次人物资料快照，刷新或开始新会话不会替换已打开的详情。

窗口默认置顶，提供置顶开关、拖动手柄和关闭按钮，可拉伸调整尺寸；初始大小为 440×700，并受显示器可用区域约束。背景不透明度可设为 **30%–100%**，默认 76%，只改变面板背景，不改变文字与数值。不提供地区筛选或鼠标穿透；透明区域仍属于窗口的矩形命中范围。

模块通过可选 `host.surface.open(...)` 请求 `view: 'statistics'`，独立页根据 `host.surface.context` 渲染排行，关闭、置顶和拖动分别使用 `close()`、`setAlwaysOnTop()` 与 `startDrag()`。框架只承载通用窗口和 iframe，不导入塔防组件、接管统计规则或接受任意 URL。完整契约见[模块包说明](module-packages.md#可选模块第二视图)。新窗口不会更新游戏内采集脚本；旧入口缺失的新字段仍需先退出游戏、移除旧入口并恢复原包，再安装当前入口、重启游戏。

### 验证边界

源码已具备上述入口与失败处理，固定采集脚本随模块构建分发；旧 `.local/tower-live-probe` 实验目录不是构建来源。历史上，0.5.2 已在不含真实存档的游戏副本中验证真实引擎启动与持续采集心跳，并已将修复入口安装回用户游戏；用户已重启确认画面正常，真实采集日志也显示初始化成功且无错误。后续已核对用户 OpenDesk 选择并运行 0.5.2 页签。0.5.3 修复未填写目录时的错误状态提示，当时采集脚本与 0.5.2 一致，无需重装。以上历史结果不代表当前新增采集字段已验收。

0.6.1、0.7.0、0.7.1、0.8.0、0.8.1 本地包保持不可变。0.8.2 已从干净源码构建，冻结 worker 验证了 1,204 条合成事件与 35 次 RPC，覆盖历史工作/伤害明细淘汰后的快照复算、错误身份及篡改拒绝；App 的核心及模块原生 smoke 通过，含共享 worker 的第二视图生命周期。新布局在实际游戏上的透明视觉效果尚未验收，本轮没有替用户安装 App 或切换个人页签选择。此前已只读核对游戏内三份采集脚本与当前源码一致，本次明细公式修复不需要重装入口；本次发布没有修改游戏。自动化、合成 NW.js 链路、浏览器 fixture、构建和桌面检查分别记录在[验证记录](verification.md)，不能互相替代。**真实游戏内的实际工作/命中归属和数值、新字段覆盖与长时间性能仍未验证**；不据引擎就绪、合成事件通过或公开发布声称实际玩法已经验收。游戏内入口、页签与宿主版本是分别核对的状态。

## 规划优先级

先用可用的已摆/仓库灵物和现有置物台提高渡劫台灵气，在最高灵气候选中减少需要移动的人物与建筑/设施，再减少灵物更换及搬动距离。人物、设施、资源与建筑的占位、台等级和可搬迁性都参与检查。

「灵气已达上界」与「迁移数量最少」是两种不同结论，界面分别报告。只有取得对应证明的方案才标为精确最优；搜索所得结果会保留限制说明。没有可验证的合法摆法时，返回阻塞原因，不以空步骤或部分布置冒充成功。

仓库灵物参与的是更换现有置物台内容，不凭空创建新台。不拆除实体、不忽略人物占格、不假定未知游戏版本具有相同规则。游戏规则取自当前安装包，具体核对记录见 `tower-game-rules.md`。

当前保持有附属设施的主体建筑、被占用的建筑、原生资源和特殊地形不动；设施仍需留在所属建筑的有效范围内。最优性结论包含这些约束。装卸按先取下、再迁移、最后放置的顺序生成，仓库必须容得下中间取下的灵物；空槽不足时明确阻塞，不假定仓库无限大，也暂不搜索交替装卸顺序。

## 数据与接口

- `tower.discover({})`：只检查程序或工程的父目录是否为游戏安装目录。
- `tower.inspect({gameDir, saveId?})`：列出已识别存档，读取指定或最近存档并返回规范化地图与灵物。
- `tower.analyze({gameDir, saveId?, platformId?})`：重新读取存档、校验规则并生成方案。
- `tower.visuals({gameDir, iconKeys})`：按已核实的动画编号读取对应人物/物品图标，最多 32 个一批；裁成最长 64 像素 PNG 后返回。客户端分批缓存，图标失败时保留文字和分析并显示提示。
- `tower.capture.status({gameDir})`：读取版本、安装、进程与采集流状态，同时返回本轮统计。`installed`、`gameRunning` 与 `updateRequired` 为 `boolean | null`，分别表示独立核实的结果，`null` 是尚无法核实；更新状态比较已安装脚本与当前包，不由页签版本号猜测。错误保留原因且不开放安装/移除。
- `tower.capture.install({gameDir})`：显式备份并安装固定采集入口；要求游戏已关闭、统计未运行。
- `tower.capture.remove({gameDir})`：核对安装/备份摘要后恢复原游戏包；要求游戏已关闭、统计未运行。
- `tower.statistics.start({gameDir})`：从当前采集序号开始新会话，清空上一轮累计与明细。
- `tower.statistics.stop({gameDir})`：读取可用的最后事件并结束计时，保留本轮结果；中断状态不会伪装成正常停止。
- `tower.statistics.status({gameDir})`：刷新并返回采集状态与统计快照，与 `capture.status` 使用同一后台权威。
- `tower.statistics.explain({gameDir, sequence, sessionId?})`：严格按序号从滚动明细或每组最近缓存中读取原始事件深拷贝，返回会话 ID、当时人物快照、伤害或工作公式、复算与原始项。主伤害另返回局部敏感度；缺少公式或已淘汰时明确说明。当前前端始终传入会话 ID，旧会话的序号不能误读新会话事件，也不回退读取其他序号。
- `tower.statistics.explain({gameDir, latest, sessionId})`：0.7.1 在同一方法中新增的汇总读取形式，必须传入会话 ID，不能同时传入 `sequence`。`latest` 对工作为 `{kind: 'work', personId, category}`，对攻击为 `{kind: 'damage', personId, attackKind, skillId}`；后台按该组和会话原子读取处理请求时最近一次事件，返回事件、实际序号和公式快照，前端成功后固定该事件。此形式不改变历史明细的严格序号语义。
- `tower.statistics.explain({gameDir, sequence, sessionId, snapshot})`：0.8.1 增加的逐次明细读取形式。`snapshot` 是原事件的 `detailSnapshot: {schemaVersion: 1, payload: string, signature: string}`；后台按所属目录实例验签，并核对请求的会话与序号，再调用既有工作/伤害复算。校验失败不降级查询其他事件，读取不切换当前游戏目录、不轮询或更改累计。

六个采集/统计控制方法统一返回 `{schemaVersion: 1, capture, statistics}`。采集状态为 `not-installed`、`waiting`、`connected`、`stale` 或 `error`，另有独立的游戏进程检测字段；进程存在不证明事件流已连接。统计状态为 `idle`、`running`、`stopped` 或 `interrupted`，带会话 ID 与中断原因。`statistics.people`、`workCategories` 与 `summary` 提供稳定人物行、工作列和汇总，权威累计只由 worker 维护。滚动 `events` 的 `detailSnapshot` 携带原事件输入及当时人物资料，前端只缓存载荷；详细复算与解析后的人物资料通过 `explain` 返回；前端固定选中副本并按请求代次拒绝迟到响应，不将人物最新资料冒充旧事件资料。

方法拒绝额外参数、相对游戏目录、网络路径和非法编号。存档方法只读取已识别的游戏包、图标与存档；采集写入限定于已核验安装目录的包和 `.opendesk-capture`，并拒绝符号链接/目录重定向。模块不提供任意文件读取或脚本执行接口。正常业务错误不会把健康 worker 误当成崩溃。

应用工作区、游戏安装目录和真实存档不入库。前端不在浏览器预览中冒充桌面宿主；浏览器模式会明确提示读取能力不可用。

图标来源为当前游戏包，模块用锁定的 Pillow 读取，不执行其中的脚本。图片只在内存处理并限制压缩文件大小、解码像素和返回大小。导出 SVG 内嵌小图标与文字，包含悬停详情；应用中的点击详情面板不转换成可执行 SVG 脚本。
