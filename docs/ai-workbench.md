# AI 工作台

AI 是独立 `ai-workbench` 页签包，使用 hostApi 2 的 Web App 机制。宿主只增加通用只读工具中介，模型适配、会话与提示内容留在插件后台；业务工具仍归各业务插件。2026-10-29 已正式发布 [AI 工作台 0.4.4](https://github.com/utxnimda/OpenDesk/releases/tag/modules%2Fai-workbench%2Fv0.4.4)，推荐搭配 [OpenDesk 0.19.3](https://github.com/utxnimda/OpenDesk/releases/tag/v0.19.3)。App 只随附塔防 0.9.3，AI 需独立下载导入；三个 Release 均从干净提交 `92c22f21d21f5287e8acb515d1de4509ed1bec50` 构建，14 个远端附件已重新下载并核对 SHA-256。既有开发包保留，下载与历史版本见[下载索引](downloads.md)。

## 当前实现范围

- OpenAI Responses 和 Chat Completions 兼容接口：连接管理、动态 `/models`、手填模型、流式回答、历史会话、停止、错误处理。
- Codex App Server：发现模型、新建与继续本插件保存的线程、增量输出、审批、中断和拥有进程回收。默认 `read-only` / `on-request`，不启动桌面 Codex、不接管其任意已有会话。
- Cursor Agent：通过官方 ACP 连接独立 CLI，动态模型目录、创建和恢复本插件保存的会话、Ask 模式、流式输出、一次性审批与取消。不把 Cursor 编辑器启动器当作 Agent，也不通过编辑器 UI 输入。
- Codex 工作区：用户显式读取本机 app-server 的 `project/list`，显示已登记项目及目录可用性，选择后用于新对话 CWD。该实验性接口以已安装 CLI 能力为准，不支持时提示更新或手填，不扫描私有数据库或导入旧聊天。
- 模型以完整下拉目录展示，另保留手填入口；已有会话空闲时可以切换模型。后端拒绝运行中修改，只有确认保存后才更新显示；网络结果不明时核对权威会话，无法确认则暂停发送。
- 每个本地模型的推理、速度、上下文等参数来自该模型真实目录，不按名称猜能力。Codex 支持目录提供的 effort 和速度档；Cursor 使用官方参数化 ACP 设置并核对服务端实际值。API `/models` 没有提供同等参数契约时不显示虚构的通用选项。
- 左侧按 Agent 类型 → 工作区 → OpenDesk 已有对话组织，合并同类型同目录；自动检测和手工连接都参与。工作区可以从原 App/Agent 登记目录读取，或仅添加到 OpenDesk；原软件聊天不会自动导入。
- API 会话可调用经宿主授权的只读插件工具。正式塔防 0.9.3 延续 0.9.0 引入的当前统计摘要接口，使用已经打开的同一后台，不启动采集、不读取任意路径。
- Vue 界面使用单一消息滚动区，支持小窗口，并从 0.1.4 起完整跟随宿主七种风格及七种配色。按本轮授权，进入页签会检测本地程序并读取工作区元数据；恢复焦点只刷新本地健康状态。模型刷新和发送消息仍是显式操作，目录读取不执行推理。

WorkBuddy、通用 MCP 服务、可写业务工具、自动执行工作流以及跨插件无界面租约仍是后续范围。本地 Codex/Cursor 暂不连接 OpenDesk 动态工具列表；API 会话具备该工具闭环。工作目录只是任务 CWD，代理的只读策略不能描述为只能读取该目录的操作系统沙箱。模型目录不等同于账户对每个模型都具备调用权限，实际请求失败会显示提供方错误。

## 使用

1. 从 [AI 工作台 0.4.4 Release](https://github.com/utxnimda/OpenDesk/releases/tag/modules%2Fai-workbench%2Fv0.4.4) 下载 `ai-workbench-0.4.4.ndpkg`，在「功能管理」导入、选择版本并启用。本地构建路径为 `dist/modules/ai-workbench/0.4.4/ai-workbench-0.4.4.ndpkg`。
2. 打开 AI 工作台，在「连接与设置」选择 API 类型，填写服务地址和 Key，保存后读取模型；API 类型必须与服务端匹配。
3. 使用 Codex 时选择左侧工作区，或填写已有工作目录；建议留空可执行路径，依次通过 PATH、Codex App 安装目录查找。严格匹配当前用户官方 `OpenAI/Codex/bin/<版本>/codex.exe` 的失效旧路径可解析到同一安装根的当前版本，保留原连接及会话身份。任意手填路径失效不会回退到另一个程序。首次登录使用 Codex 官方流程，工作台不索取或复制认证文件。
4. 使用 Cursor 时先按[官方说明](https://cursor.com/docs/cli/installation)安装 Agent CLI 并执行 `agent login`；编辑器登录不保证 CLI 已登录。可留空使用官方安装位置/PATH，或填写官方包内 `cursor-agent.cmd` 的绝对路径，后台解析相邻运行时后直接启动，不运行任意 shell。当前默认 Ask 模式，未支持的交互明确拒绝。
5. 点击输入框旁的刷新按钮读取模型，完整目录不会按当前模型文字过滤。输入框下方显示该模型的实际参数；旧会话未设置的参数显示「跟随原设置」，新模型使用明确的目录默认值。新对话绑定连接，回合间可换模型与参数；切换提供方使用新对话，不冒充完整的原生会话迁移。
6. 需要读取插件工具时，先打开支持工具导出的目标页签，再返回 AI 页签刷新工具。勾选需要的工具并接受宿主显示的具体授权，然后发送 API 消息。

API 聊天本身可在 0.18.0 Web App 宿主运行；跨插件工具需要 0.19.0 起提供的宿主能力，推荐使用已正式发布的 0.19.3。旧宿主不显示假可用工具。升级 App 不自动切换用户固定的塔防版本；旧包没有导出工具时不会被自动绕过。

0.4.4 修复流式回答终态读取竞态：任务状态、末尾事件与游标在同一服务锁下读取，确保界面收到「已完成」时也能取得完整的末尾回答事件。新增回归测试暂停最终事件发布来验证这一边界，旧的无锁读取会在该测试失败。修复不改变 dataSchema，也不执行额外模型请求。

## Agent 目录、连接与模型参数

`GET /api/state` 对注册连接做本地文件健康检查；程序存在只表示可启动，不冒充账号已登录或模型有额度。同类型、同实际程序、同默认工作区的连接以 `duplicateOf` 归并新任务入口，优先保留自动发现路径；旧连接记录和历史绑定不删除。恢复焦点后若原选择失效，界面清空连接/模型选择并保留消息草稿，要求用户重新选择，不把草稿自动转给另一个提供方。只有后端明确标记的同类型等价重复连接可以归并。

`POST /api/agents/refresh {}` 识别已安装的 Codex/Cursor，在不存在可用注册时创建来源为 `detected` 的本机登记，然后合并连接默认目录、OpenDesk 手动目录、已有对话目录及原生工具目录。Codex 使用 `project/list`；Cursor 使用 ACP `session/list` 的 cwd，以及 App `storage.json` 的已知目录字段、只读 `state.vscdb` 中唯一固定的 `history.recentlyOpenedPathsList` 键。读取有字节数、层级、条数限制，不扫描凭据或聊天正文、不复制数据库、不加载外部会话。远程和已不存在的目录标为不可用；部分目录读取失败会显示 warning，已有目录继续可见。

从 0.3.1 起，左树与目录选择器隐藏不可用目录；原登记和历史数据保留，目录恢复后刷新即可重新显示。空目录默认折叠，有对话或当前选中目录展开。类型旁「+」通过 `POST /api/workspaces {connectionId,path,label?}` 保存 OpenDesk 自己的目录项，不改 Codex/Cursor 项目注册。相同类型与规范化目录仅显示一个节点，多连接来源可查看，历史对话仍保留实际连接 ID。API 没有原生工作区目录时可手动添加，旧会话归入未分配工作区。

模型目录带 `parameters[{id,label,options,defaultValue}]`。模型与参数一起提交到新会话，或通过 `POST /api/conversations/<id>/model {model,modelOptions}` 更新；运行中不允许修改。参数先按后台持有的目录校验，再在实际执行进程中核对。目录缓存绑定连接类型、地址、程序、工作目录及凭据引用；编辑或在途目录身份改变时失效，不能把旧目录能力写回新连接。

Codex `reasoningEffort` 传入 `turn/start.effort`；速度传入 `serviceTierForTurn`：`default` 明确选择标准速度，Fast 使用模型目录真实返回的 `priority`。省略速度会继承线程设置，界面不把它标为标准。Fast 的目录说明会提示较高用量。Cursor 显式参数需要协商 `parameterizedModelPicker`，通过 `session/set_config_option` 设置官方模型 base 和各参数，并确认返回值后才发送消息；不能用拼接 variant ID 冒充参数已生效。旧 canonical ID 保持兼容，`providerModelId` 用于精确定位对应模型。

数据 schema 仍为 1，本轮只添加可选 `modelOptions`/连接来源字段及独立 `workspaces` 表，不删除或改写旧聊天。旧版本可保留这些字段，但没有参数和目录树功能，不应使用旧包验证新参数行为。

## 外观同步

宿主仍是外观的唯一拥有者。包装页从已校验的模块 SDK 接收外观，将 `theme`、`uiStyle` 和固定的 `surfaceEffects` 一起传给内层 AI 文档；初次打开通过片段初始化，之后通过校验 source、origin、nonce 的版本化消息更新。风格独立变化、配色变化、设置预览及取消预览都走同一条链路，页面载入后还会重新同步最新状态。

AI 页面直接复用宿主的主题、风格和静态材质样式来源，仅保留自身会话/聊天/设置面板布局。简洁、Codex、Cursor、现代 Web、二次元、深海透明和薄荷奶油各自采用对应密度、圆角及表面；配色独立选择，dark 与 graphite 不再混为同一绿色色板，非薄荷风格不会被固定薄荷颜色覆盖。

0.2.1 将聊天信息层级统一为紧凑会话侧栏、正文和底部输入区，连接设置按需展开。模型、连接和工作目录放在输入区附近，移除装饰星形、宣传式标题及重复卡片。操作图标复用工程已有 Lucide，统一尺寸、描边及居中规则；不增加新的图标依赖。不同风格继续影响颜色、材质、密度与圆角，聊天控件的位置保持一致。

外观更新仅改变当前文档的样式属性，不重新创建 iframe、不重启后台、不改连接或会话，也不清空正在编辑的消息/连接草稿。旧包与原有数据保留；此修复只更新 AI 页签，不要求宿主重新打包。

## 单层工作面、侧栏宽度与回答排版

0.4.2 引入的布局改进已随正式 0.4.4 交付；配合宿主 0.19.3，功能页不再重复展示宿主面包屑、版本状态横条或外层圆卡；加载/失败仍明确显示，版本可在功能管理查看。AI 自身清除 SDK 默认 body 内边距，侧栏与聊天区连续填满工作面；颜色和材质仍来自宿主，内容控件保留协调的小圆角。旧独立插件仍负责自己的内部样式，宿主不跨 iframe 改写其 DOM。

桌面模式下拖动工作区侧栏右侧的分隔线可调整宽度。支持方向键微调、Shift 加速、Home/End 到达边界、双击或 Enter 复位；拖动中 Esc 取消。默认 238 px，保存范围 180–480 px，窗口较窄时临时限制宽度以保留聊天空间；≤700 px 使用折叠抽屉并隐藏分隔线。临时视口夹宽不写入偏好。

布局通过 `state.layout` 和 `POST /api/layout {sidebarWidth}` 由 Python 保存，使用 schema 1 的独立 preferences 记录；只在完成拖动或键盘调整后写入。前端串行合并保存请求，失败明确提示重试，状态刷新不覆盖未确认草稿。未知/损坏的布局记录拒绝读取和覆盖，不悄悄重置。此数据扩展不删除原聊天、连接或工作区。

回答支持标题、粗体/斜体、列表、引用、删除线、表格、行内代码和 HTTP(S) 链接。代码围栏按显式语言进行语法高亮，并提供复制原始代码按钮；未知语言按原文显示，未闭合的流式代码围栏仍保持代码格式。代码和表格只在自己的区域横向滚动，不撑宽整个聊天页面。超过 20,000 字符的代码块保留完整纯文本；超过 300,000 字符的整条消息降级为完整原文并提示。

Markdown 经解析后转为白名单 Vue 节点，不执行模型提供的 HTML；图片只显示替代文字，不自动向外部请求。链接限定无内嵌凭据的 HTTP(S)，使用新窗口、noopener/noreferrer/no-referrer。AI 内层采用已有 API2 外层允许的 popup sandbox 项，仍不允许导航顶层；没有增加宿主 shell 或文件权限。只有 highlight.js 产生的已转义语法 span 使用 HTML 渲染。复制由用户点击触发，不读取剪贴板，失败时明确提示手动复制。

新增渲染依赖锁定为 markdown-it 15.0.3 与 highlight.js 11.12.0；许可证说明位于 `plugins/ai-workbench/frontend/public/THIRD-PARTY-NOTICES.txt` 并随 AI 包的 web 资源交付。

## 工具契约 v1

目标插件在 manifest.methods 显式登记 `tools.describe`，并以短 RPC 返回 `{contractVersion:1,tools:[...]}`。每个工具声明 `name`、已登记的实际 `method`、`title`、`description`、`contractVersion:1`、`readOnly:true`，以及严格空对象 `inputSchema`。第一版只支持无参数只读工具，不向模型开放原有全部内部方法，也不接受执行命令或路径参数。

宿主向调用方公开工具 ID、目标模块 ID、版本、摘要、运行代次和说明，不公开目标 token。原生确认绑定当时的完整工具目录快照；确认过程中目录、版本或实例改变会拒绝。授权仅存在于内存中。调用复用目标正在运行的实例，参数重新校验，结果限 64 KiB 并带来源身份；生命周期转换与已接纳的短读协调，不把旧调用重定向到新版。

目标未打开或未完成 UI 握手时不会伪造就绪，也不会额外启动第二份业务状态。`@插件`、命令模板和 MCP 适配可以以后消费同一工具契约，当前没有把特殊文本解析成可执行指令。

## 数据和进程

插件数据由宿主提供的 `OPENDESK_MODULE_DATA_DIR` 定位，SQLite 带版本；未知格式拒绝，未完成运行在重启后记录为中断。API Key 由通用 Python 凭据服务使用 Windows 用户绑定 DPAPI 加密，SQLite 只存引用；不会在状态接口、聊天、普通日志或包中返回密钥。改 API 地址时不能自动把旧 Key 发给新地址。

HTTP 服务仅绑定 `127.0.0.1` 随机端口，API 校验 Host、Origin 和每次进程独立 Bearer；令牌使用片段传入界面，不作为请求 URL 查询。拒绝跨源 API 和携带 Key 的重定向。普通本机进程仍非安全沙箱，不宣称可阻挡同用户权限的任意恶意代码。

每个会话最多一个活动任务，全局最多两个。取消先进入 cancelling；确认停止后才变为 cancelled。API 流中断、缺少完成事件或空结果不会假成功。API 工具循环最多八轮，只执行该次消息的工具白名单；结果重发不重复执行工具。

Codex 使用拥有的子进程与 Windows Job，协议失败、取消和退出都只处理本次启动的进程。不转出原始推理或原始 stderr。无法确认回收时状态为 unknown，保留回收句柄供关闭排空重试。hostApi 2 的 `module.prepareShutdown` 先停止接收新任务并请求取消，仍有活动或未回收进程时不会宣称 ready。

Cursor 使用相同的进程所有权约束，经 ACP 确认 Ask 模式和所选模型后才发送提示词；不启用 force/yolo 或自动批准 MCP。仅返回当前会话的回答文本，不重复显示恢复会话时的历史，不公开内部推理或原始错误流。目录查询也计入后台活动；查询进程清理失败同样保留重试句柄，防止关闭流程误报已排空。官方 CLI 作为本机依赖单独安装，不随 `.ndpkg` 或源码 Git 分发。

部署工作台等私有模块不会因 AI 插件而被扫描、复制或公开；当前也没有为其导出工具。未来读取其内容并发给模型，需要独立、明确的数据授权。

## 开发与验证

```powershell
npm run test:ai
npm run build:module -- ai-workbench
```

构建复用根目录锁定的 Vue/Vite/Python，不依赖用户安装 Python。可用 `OPENDESK_AI_PYTHON` 或 `.local/dev.json` 的 `aiPython` 指定打包解释器，默认回退到工程既有 Python 设置。包中仅含包装页面、已编译 AI 页面、后台和冻结依赖；测试 fixture、聊天、Key、数据库及原始资料不打包。

AI 0.4.4 已作为独立正式页签发布；加入 `publicModules` 只明确可公开构建范围，不代表获得未来自动发布授权。App 的 `bundledModules` 仍只有塔防助手。每次代码修正后，已使用过的同 ID/版本包保留原字节，新版本独立出包。发布仍按[发布手册](releasing.md)及当次用户授权执行。

测试区分本地协议模拟、真实模型目录、冻结包、浏览器和原生桌面。没有配置真实 API Key 或执行实际推理时，不把模拟回答称作真实模型验收。实际结果见[验证记录](verification.md)。
