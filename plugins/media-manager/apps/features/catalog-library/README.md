# 作品库

页面读取本地作品数据。来源同步、作品编辑和章节文件绑定均通过作品 DB 的公共编辑服务保存，不使用来源 API 作为页面的实时数据源。

## 快捷筛选

作品卡片提供小／中／大／自动四档，默认中号。固定档最小宽度分别为 100／126／240px，自动档以约 160px 为目标按实际容器宽度排布。通过公共偏好接口独立保存 `nimda.catalog-library.card-size`，调整尺寸不重新请求作品列表，也不影响卡片／列表偏好。

卡片标题、基本信息、资源摘要都保持单行。长标题省略并保留完整悬浮提示；基础信息优先保留年份和评分，放不下的字段及分类通过 `…` 浮层查看。资源摘要显示为 `4版 BDRip/CK BDRip/VCB`，每个标签包含原始压制格式、组简称及重复数 `×N`；鼠标悬浮显示 `BDRip/CK·澄空学园` 等完整信息，也可点击查看。相同格式／组的重复资源合并标签，总资源数不去重；同组不同格式仍分别计数。按实测宽度尽量列出全部完整标签，只有单行放不下时才显示 `+N`，在独立浮层列出全部版本，不增加卡片高度。空组显示 `—`，未知简称与大小写原样保留，VCBM 等组合不会并为 VCB。

卡片与收集列表共用 `framework/frontend/src/common/press-summary.js` 的枚举标签、排序、分组和空值规则；卡片附加投影使用现有 `/api/config` 的组注册表解析全称。`card-layout.js` 负责宽度计算、字体／窗口变化重排及生命周期清理；`card-popover.js` 负责可键盘操作的单实例浮层。列表摘要只读取作品 DB，不扫描磁盘或返回资源路径。

作品库支持国家、媒体类型（TV/电影/OVA 等）、压制组、压制格式四个枚举下拉，复用作品编辑器的枚举和中文标签；历史值仍可筛选，未填写值显示为 `----`。压制组与格式必须命中同一条资源，计数按作品去重。搜索词仍为输入框，原有品类、年份及系列筛选保留。筛选只读本地 DB，不扫描媒体硬盘。

国家／媒体类型、年份／系列、压制组／格式统一放在右侧“作品信息、时间与分类、本地资源”三组。点击右缘“筛选”可收起为窄边栏，作品区域自动扩展；已选条件仍生效，主区域保留可移除标签，边栏显示当前六项筛选的选中数量。收起／展开仅改变界面，不重新请求作品列表；通过公共偏好接口保存 `nimda.catalog-library.sidebar-collapsed`，清除筛选不清除此偏好。搜索使用搜索框内右侧的圆形图标按钮，搜索与筛选按钮共用 36px 宽度和右侧缩进，保持纵向对齐。窄窗口改为顶部入口和分组表单，不增加独立滚动条。

## 外部作品来源

“来源”页支持 Bangumi、TMDB（电视剧）和中文维基百科。搜索、选择条目并预览后，勾选需要采用的字段再确认；不自动覆盖未选择的作品字段。来源名称与本地名称不同时，确认会追加为别名并与手写别名去重。全部来源共用签名预览、版本检查、正式作品写入与备份流程，不修改媒体文件。点击来源条目链接可打开对应网站。

### 多来源管理与统一刷新

- 详情顶部的“刷新作品数据”刷新当前已启用的全部关联；来源页列出条目名称、网站链接、范围、主／补充角色和启用状态。支持单来源刷新、添加、重新选择、启停和移除关联。已绑定作品的搜索表单按需展开。
- 尚未配置来源时，动画默认预选 Bangumi；韩剧默认预选 TMDB 主来源和中文维基百科补充来源。默认只决定平台，不会按名称猜测并绑定外部条目。首次关联 TMDB 后，尚缺的维基百科平台仍可直接选取；保存过的人工选择、停用与移除不会被默认策略恢复。
- `source_refs` 中每条关联有稳定 `binding_id`、`enabled`、`role` 和可选 `title`。旧记录只在读取投影中补默认值，不批量迁移。重新选择保留指定关联的身份和用户设置，替换该关联，而不是追加一条旧、新并存的关联；重复条目和范围会拒绝。移除仅删除关联，不删除已导入字段、媒体、人物或历史来源快照。
- 一次刷新按来源分别获取，有界处理网络请求并隔离失败。全部成功候选组成一份签名差异预览；全失败时不能确认。字段可选来源，别名合并去重；主标题、章节及封面不由补充来源自动接管。存在多个主来源冲突、已有无导入记录的数据或手工修改（包括主动清空）时，默认不勾选覆盖。来源空值不清空已有数据。
- 确认只读取已校验的本地快照，经统一作品编辑服务进行一次版本校验保存；多个 Bangumi / TMDB 人物提案复用人物批量事务。预览期间作品发生变化、快照被改动或令牌失效时拒绝保存并要求重新预览。来源警告、失败对象与阶段进入公共处理详情和日志。
- `source_policy_config` 保存平台目标及人工配置状态；旧作品编辑页面也保留此扩展。聚合预览位于 `sources/_sync/<SHA-256>.json`，短签名引用该快照，避免把全部来源令牌放入一个超长令牌。

接口：`POST /api/catalog-library/provider/sync-preview` 接收 `ref` 和可选 `binding_ids`；`sync-apply` 接收 `ref`、`preview_token`、`selected_fields` 和可选 `field_choices`（字段名到关联 ID）。`binding-update` 接收 `ref`、`binding_id`、`action`（`enable`／`disable`／`remove`／`set-role`），设置角色时附带 `role`。原有 `provider/preview` 可传 `replace_binding_id`、`binding_role`，替换意图签入预览。预览在网络任务队列执行，确认和关联管理在磁盘任务队列执行。

职责：`source_bindings.py` 负责纯本地关联投影与默认策略；`source_sync.py` 聚合预览、字段选择和一次提交；各来源继续共用 `providers.py` 的快照、安全校验和导入准备逻辑。

- TMDB 按“电视剧 ID + 季编号”关联；默认第 1 季，0 为特别篇。不会把整个多季系列的章节合并到单个本地作品。可导入原名、中文别名、简介、当季首播日期、章节、本地封面，以及当季演员和制作人员。章节标题优先原语言保存，中文标题另存，显示仍遵循本地语言配置；TMDB 的分钟时长转为来源 `duration_seconds`。原语言获取失败会警告并保留可用中文数据；未提供的字段不用于清空本地数据。完结日期不根据章节日期猜测。
- 中文维基百科用于补充中文名称、别名、简介与可明确解析的首播/完结日期。可以搜索名称或粘贴 `https://zh.wikipedia.org/wiki/…` 的条目链接；引用保存规范页 ID、修订 ID、条目/修订链接与 CC BY-SA 4.0 署名信息。仅解析支持的电视剧信息框中的明确日期，不从正文或最大章节日期推断；不改写章节或封面。已确认关联的作品条目还可在 TMDB 人物更新中补充缺失的中文姓名与饰演角色，规则见下文。消歧义页不能直接导入。
- 原始快照分别保存在 `data/features/catalog-library/sources/{bangumi,tmdb,wikipedia}/<SHA-256>.json`；正式展示仍来自本地作品 YAML。已退役来源的旧快照保留。确认只读取预览中已校验的本地快照，不二次联网。来源链接及字段来源写入 `source_refs`、`metadata.field_sources`，保持可追溯。维基百科内容使用与再分发需遵守其署名/相同方式共享许可；图片权利按各来源的授权约定处理。

### TMDB 服务端凭据

在 TMDB 账户的 API 设置申请 **API Read Access Token**，不是普通网站登录密码。优先读取服务端环境变量 `TMDB_API_READ_ACCESS_TOKEN`；未设置时读取共享工作区的 `config/features/catalog-library/providers.local.yaml`：

```yaml
tmdb:
  read_access_token: "填写你的 API Read Access Token"
```

可参考 `providers.example.yaml`。`providers.local.yaml` 已被 Git 忽略；不要加入 SVN、打包分发或复制到作品 DB。环境变量改变后需重启应用；文件配置会在请求时读取。凭据只发送到固定 TMDB HTTPS API 的 Authorization 请求头，不放进 URL、前端、来源快照或处理日志。API 与图片下载沿用系统/环境代理；拒绝跨域重定向，限定响应大小和处理时限。

This product uses the TMDB API but is not endorsed or certified by TMDB.

TMDB 官方说明：[认证](https://developer.themoviedb.org/docs/authentication-application)、[电视剧](https://developer.themoviedb.org/reference/tv-series-details)、[季与章节](https://developer.themoviedb.org/reference/tv-season-details)、[许可与署名](https://developer.themoviedb.org/docs/faq)。

## 本地章节播放

在作品详情的“资源”页点击某行的“设为播放资源”。应用识别该目录并尝试读取视频时长，成功保存后该行显示同尺寸的“当前播放资源”禁用按钮；切换失败保留原选择。完整扫描到视频即可以设置，不要求所有章节都已匹配，也不要求时长读取成功。当前资源改变编号草稿后，同一按钮变为可用的“应用”，不会额外增加控件或行高。

当来源章节同时提供不同的本作编号与续接编号（例如 Bangumi `ep=1～13`、`sort=14～26`）时，“章节”页在同一集数列显示 `01(#14)`；普通作品显示 `01`，悬停可查看完整编号含义。播放按钮仍位于集数旁。在“资源”页为每个资源选择按“本作”或“续接”编号识别，再点击“应用”或“设为播放”保存；编号选择、当前标记和操作按钮横向排列，不增加行数。下拉框本身不会修改 DB。已有记录默认沿用本作编号，切换失败保留原配置；同一目录被多个作品引用时，各作品的选择相互独立。手工指定的对应关系优先且不会因切换编号方式而清除。缺失、重复或特殊章节编号不会被猜测为正片集数。

“章节”页直接展示 DB 中上次保存的匹配和时长。章节标题遵循收集类型的语言配置，悬停显示另一语言；集数右侧始终保留播放按钮，没有可播放绑定时置灰且禁用，悬停说明未绑定、未识别、待选、缺失或无资源的原因。使用系统默认播放器打开唯一匹配或手动确认的视频。列表不显示本地文件路径；“设置”弹窗中可以确认候选、选择其他已识别文件、输入对应的相对路径，或恢复自动匹配。“重新识别文件”将重新扫描并读取时长，更新 DB 缓存。

“批量设置”可同时选择章节与已识别视频，跨页保留选择；选中数量一致后按章节顺序、文件自然顺序生成对应预览，可分别上下调整顺序。覆盖已确认映射时展示原文件。确认后一次调用原 `playback/save`，只提交改变的映射，保留未选章节，继续校验 DB 与扫描版本；失败保留预览，不移动或修改媒体文件。

- 优先读取所选 DB 播放资源目录直属的 `Disc`、`_Disc`、`作品名_格式_Disc`；存在 Disc 时不混入资源根目录的其他视频。没有 Disc 时，把当前播放资源目录当作 Disc。不移动、不重命名、不修改媒体。
- Disc 内平铺的视频按文件名集数匹配；存在单集子目录时，进入各单集目录查找媒体文件。支持 `EP01`、`Live_01`、`[01]`、` - 01`、`作品_01`、`第1集`、`S01E01` 等明确标记。单集目录集数可辅助识别；没有文件名集数时，仅对该单集目录唯一的正片视频兜底，不从年份或分辨率推断集数。
- 字幕、音轨、字体以及 OP/ED/CM 等附属资源不作为正片匹配；文件名与单集目录集数冲突、多个视频版本、扫描不完整或多季混合时不会自动任选，保留手动确认。
- 特别篇或无明确集数的视频可以手动对应。章节身份缺失或重复时，先修复章节数据，避免保存不稳定映射。
- 当前播放资源、识别快照、真实媒体时长及手工对应关系均保存在作品记录的 `local_playback` 扩展字段。`selected_resource_key` 指向当前资源；`resources` 按资源身份哈希存放 `identity`、`assignments`、`scan` 及可选的 `numbering_mode`（`local`／`continuous`，缺省 `local`）。编号方式不参与资源身份或章节身份计算。`scan` 包含目录身份、识别时间和文件签名，`assignments` 按章节 ID（无 ID 时使用类型与集数）保存手工对应。旧版仅含 `assignments` 的记录保持兼容，来源同步与旧编辑界面会保留该字段。
- 页面加载只读 DB，不扫描媒体或读取时长。播放与手工保存前重新检查作品版本、当前播放资源、文件快照及集数识别结果；文件、DB 或识别结果变化后须重新识别。更新识别规则后，点击一次“重新识别文件”刷新已有缓存。只允许范围内的普通视频文件，拒绝链接、越界路径和可执行文件。
- 识别时使用本机已有的 `ffprobe`，采用单文件超时和整体时间预算，并按文件状态缓存成功结果。缺工具、超时或无法读取时长均不阻止资源设置和文件匹配保存；显示时优先本地时长，再回退到本地保存的来源章节 `duration_seconds` / `duration`，都没有才显示 `—`。悬停提示区分“本地视频时长”和“来源章节时长”；来源值不写入媒体扫描快照，不冒充实测时长。API 的 `duration_seconds=0` 按未知处理。
- 操作进度和结果接入公共处理详情与日志系统。默认播放器的实际播放进度不由应用控制。

职责划分：`frontend/chapter-player.js` 管理章节交互；`backend/catalog_library/chapter_numbers.py` 提供共享的编号校验和只读双编号投影；`backend/catalog_library/playback.py` 负责 DB 资源与章节对应；`framework/backend/work_catalog_yaml/common/media_files.py` 提供可复用的安全媒体扫描、时长读取与系统打开能力。

## 批量关联资源目录

作品“资源”页的“批量关联资源目录”支持在资源库中多选目录，或粘贴多行绝对/相对路径。所有目录必须位于当前作品根目录内，不自动扩大或修改作品根目录；旧的相对作品路径由详情接口返回的 `work_directory` 安全定位，无法定位时先通过原编辑窗口修正作品根目录。

可统一填写压制格式/组，再逐项修正。字段候选复用公共枚举配置；未知格式不猜测，需要手工确认。按路径、格式、组和收集位置判重，同目录不同格式/组可保留；原资源、补充收集、人物、来源、播放及扩展数据均保留。`batch-resource-dialog.js` 使用公共 `NimdaWorkRecordForm.fromRecord/applyPatch`，由作品库原 `edits/preview → edits/apply` 保存，一次提交全部新增条目。关联只写 DB，不扫描、移动媒体或自动生成快捷方式；手填目录沿用作品编辑允许暂时离线或尚不存在路径的规则。

## 章节标题、人物与角色名语言显示

作品库主界面“显示设置”可按收集类型（品类 + 国家）选择中文或原语言优先。章节标题、人物姓名与“饰演”的角色名共用此配置：默认日本动画原语言优先、韩国电视剧中文优先，悬停显示另一种语言；任一语言缺失时回退已有名称。演员、虚拟角色、CV、制作人员以及人物详情和预览均使用同一优先级。官方原名为英文时保留英文，不根据作品国家自行转写成韩文。当前数据库中其他收集类型也会列出，并提供未单独配置类型的默认值。

配置保存到共享工作区 `config/features/catalog-library/display.yaml`，不修改作品或人物数据库。`display_settings.py` 复用公共写锁、内容版本校验、原子写入与历史备份；`/display-settings` 读取、`/display-settings/save` 按版本保存。为兼容旧数据，继续使用 `chapter_titles` 配置字段和详情中的 `chapter_title_preference`。章节、批量设置与人物展示共用 `chapter-title-format.js`，不调换或重写来源字段。

## 独立人物与角色资料

### 人物与角色图片来源

共用人物卡的“图片来源”提供 Bangumi、中文维基百科、维基共享资源、TMDB 剧照和本地选图。图片获取与人物身份关联分离：只更新该卡的 `avatar` 与图片来源证据，不新增 `source_refs`，不把演员照片自动当作角色图片，不修改作品／角色／演员关联。

- Bangumi 使用明确的角色或人物 ID／条目链接，类型必须与当前卡一致；Wiki 使用条目标题、页面 ID 或文件页，Commons 使用明确 `File:` 文件名／文件页。不按同名自动认定身份。
- TMDB 使用作品 ID／链接读取整部作品背景剧照，或填写季数、集数读取该集剧照。只提供剧照，不把海报或演员头像混入。候选最多 30 张，每页缓存 8 张；用户选中后再进入图片对比预览，API 不推测画面中的角色身份。
- 本地选图支持 JPEG／PNG／GIF／WebP，最大 2 MiB，服务端验证实际图片编码和尺寸；不接收本地路径或任意远程图片 URL。
- 预览仅创建有界图片缓存及签名计划，不改作品和人物记录。确认复用人物资料公共版本校验、历史备份及写入流程；过期预览与跨人物候选拒绝应用。手选图片保存为手动来源，后续资料刷新不会自动覆盖；清空只移除图片引用，不删缓存文件。
- Wiki 作者、许可与来源页（如有）保存在 `field_sources.avatar.image_source`，详情只读投影为 `avatar_image_source`。图片展示始终读取本地 `/api/catalog-library/people/assets/…`，不向浏览器泄露来源凭据；来源内容与图片的使用须遵守对应许可。

职责：`people_image_sources.py` 适配 Bangumi／Wikimedia，`people_image_candidates.py` 适配 TMDB 剧照，`people_images.py` 负责候选签名与图片预览，复用 `people_library.py` 保存；前端 `people-catalog/profile-images.js` 管理选图，`profile-dialog.js` 复用资料对比确认。接口为 `POST /api/catalog-library/people-library/image-candidates`、`image-preview`、`image-apply`；图片预览请求体限定 3 MiB。

### 统一身份、字段与关系确认

每个人物的标题可独立展开／收起，收起时保留待确认数量。展开人物后仅直接列出冲突、手动调整或需修正的字段；相同、空值、保留本地与默认补齐的字段统一放入“自动补齐／保持原值字段”折叠区，展开后仍可调整选择。人物和字段区的折叠状态在同一预览重新显示、异步读取与失败重试后保留，不改变字段、关联及手填值的确认结果。独立人物资料卡的来源采用预览沿用相同折叠规则；手工编辑与清空预览仍完整展示待执行修改。

Bangumi、TMDB 和中文维基的作品人物导入统一使用 `people_import.py` 与 `frontend/people-selection.js`。首先匹配本地人物库，无匹配的来源人物默认新建；明确来源身份匹配时复用资料卡，当前作品缺失的安全关联也默认补齐。同名和别名候选仍需核对身份。空字段默认采用新值，相同值保留本地值，来源空值不清除本地资料；同一种语言的非空内容不同才由用户勾选采用。新建、补齐和无需更新的人物统一折叠，仅字段冲突或身份歧义默认展开。所有修改仍经最终一次确认保存，预览不写入人物或作品数据库。

人物别名是增量资料：旧 `aliases` 和 `localized.aliases.<语言>` 均自动合并去重，保留原有顺序与写法，不要求逐字段确认。不同语言的名称、简介独立补齐，未确定语种不按作品国家猜测；中文姓名和简介采用下面的来源版本策略，其他同语种名称的真实冲突仍需确认。共享 `people_field_merge.py` 为作品人物导入、独立人物资料卡与顺序批次提供一致规则，预览展示实际合并结果。手动编辑、显式清空仍可替换字段，不被来源增量合并规则覆盖。

来源的 `infobox`（详细资料）通过 `people_infobox.py` 按规范化 key 拆成独立预览项，DB 仍保存原来的 key/value 数组。不同 key 合并保留，同 key 空值自动补齐，相同值保持，非空差异逐项确认；一个冲突不影响其他 key 的默认补齐。明确的别名 key 也按增量去重合并。动态字段身份使用 key 的稳定编码而不是列表位置，签名与批次版本检查保持不变；手动编辑和清空仍使用原有整块字段接口。

作品资料来源采用相同的默认原则：空值和别名并集自动预选，非空差异不预选，多来源别名合并全部已选来源，不要求任选一个。最终确认前仍可取消采用，预览不会写入数据库。

共享人物资料可选存储 `localized.name`、`localized.summary`、`localized.aliases`，按 `zh-Hans`、`zh-Hant`、`ja`、`ko`、`ko-Latn`、`en`、`und-Latn`、`und` 分开记录。`people_catalog/localization.py` 统一校验、旧字段只读投影和语言路径操作，作品导入、独立资料卡、角色合并复用该模块。不同语言补齐不会覆盖彼此；语言不明的拉丁字母内容不猜作英文名或韩文拼音。显式空语言槽保留，避免旧兼容字段在显示时复活手动清空的内容；后续来源的新非空资料仍可默认补齐。旧 YAML 保持兼容，无隐式全库迁移。

人物显示按作品的语言偏好选择本地名称和简介，中文优先时悬停尽量显示韩文／日文原名，缺失时使用已有可靠名称。编辑器按语言分组，空组折叠；已经保存多语言资料的卡片不再并列提供含义重复的旧名称编辑项。来源预览、字段来源证据、失败重试和批次中前后来源的冲突检查均使用同一语言字段路径，避免辅助来源静默覆盖主来源。

姓名与简介的来源版本由公共 `people_catalog/profile_variants.py` 管理：`profile_variants` 按字段、语言、来源保存候选，`profile_preferences` 记录人工指定来源或固定值，原来的 `localized` 仍是兼容的显示结果。身份确认后，中文姓名优先中文维基，其余译名进入别名；简介保留各来源版本而不拼接，默认优先维基。没有维基时保留已有显示或采用已明确的来源刷新。手工非空编辑固定显示；普通清空同时清理该语言槽的候选与偏好，下次来源可重新补齐。只有显式选择“手动固定当前值”才允许锁住空值。未确认身份或跳过人物时不保存来源候选。

共享人物卡的“名称与简介版本”提供逐语言来源切换和恢复自动选择，复用原有 `edit-preview` / `edit-apply`、签名与版本校验；切换前仍显示修改预览，不另开直接写库通道。候选保留每个来源身份的最新值；同一网站的多个已确认条目分别保存，不互相覆盖，更旧版本仍在资料历史和原始快照中。显示字段全部保持原值时，如有新的来源候选，独立来源预览仍可明确点击“保存来源版本”；不会自动写入或隐式迁移现有人物库。

全库目标由来源签名快照校验；搜索命中的其他资料卡按需调用 `people/selection-target` 获取字段差异，不为全库每个人提前生成完整差异。来源所有者冲突、版本变化、角色／CV 依赖未确认等会阻止保存；所有来源共用离线快照、版本检查和一次作品／人物事务，保留历史备份。

人物采用分类时，勾选本身即确认分类编辑器的当前值，无需额外切换一次下拉框。未勾选仍保持本地分类；来源为空的其他字段继续要求明确手填。人物状态与最终保存按钮共用字段校验，阻塞原因包含人物和字段名，按钮旁可直接查看具体原因。

维基人物支持两条入口：从所选作品页面明确的演员链接准备候选；或在人物页的“通过维基人物条目补充”填写最多 20 个明确条目及可选职责／饰演信息。后者调用 `people/wikipedia-preview`，不依赖 TMDB，也不按姓名搜索猜测身份；最终同样经 `people/apply` 确认保存。

### 人物与组织分类

共享资料库使用正交字段 `taxonomy.category`（人物／组织／其他实体／待分类）、`reality`（现实／虚构／待确认）、`subtype`（个人、角色、公司、工作室、团体、机体等）。`people_catalog/taxonomy.py` 与前端 `taxonomy.js` 提供公共投影、标签和枚举编辑器。公司和会社归组织，不再显示为现实人物；组织不提供人物性别／生日编辑，角色合并和饰演／CV 关系只接受相应人物类别。

旧 `type`、`kind`、UUID 和来源身份保留，用只读投影兼容，不批量改写现有 YAML。手动修改分类须经资料卡预览确认；来源刷新不会直接覆盖既有手工分类。旧 `type` 是身份兼容字段，不能再单凭它判断实体是现实人物。

作品详情提供“人物”页签。刷新作品资料时同时读取可用人物，并在作品来源预览中展示人物提案；明确选择后共用同一次作品写入保存资料与引用。单独刷新封面不读取人物。人物页签仍保留“更新人物信息”，可单独预览角色、CV、演员与制作人员资料并确认保存。多来源作品通过 `binding_id` 明确选择来源及其季/章节范围。页面正常浏览不请求来源 API，只使用本地图片缓存。

选择或替换中文维基条目时，`supplemental_people.py` 在内存中建立本次待确认的维基来源上下文。只有一个已启用 TMDB 作品／季范围时，中文与韩文角色证据补充到原 TMDB 角色身份；Wiki 独有的人员、资料和饰演关系仍保留独立候选，明确识别到同一演员时复用其资料卡。多个 TMDB 范围无法唯一归属时提示核对，不跨季猜测。作品与人物在同一预览中呈现，统一确认事务保存，原作品仍是版本与签名基准。多来源批次复用前序 TMDB 快照，将补充后的签名提案替换未补充提案，避免重复抓取和重复采用；不会因前序已读取 TMDB 而丢弃随后选择的 Wiki。单个来源失败保留已有资料，不阻断其他有效作品字段。

Wiki 独立读取优先准备作品级韩文角色与简体转换，再读取可选演员详情；主站补充已获得的作品和人物页面证据可复用。中文简介中的韩文原名引用不再把整段简介归为韩文。获取失败仍逐项记录，未获得的语言值不伪造，页面按偏好语言读取并回退到已有语言内容。

中文维基的原始修订正文不因请求的 variant 参数就被视为简体。显示内容通过官方转换结果和明确的标题变体记录 `zh-Hans` / `zh-Hant`，保留有证据的原文版本；转换失败不把原文硬标成简体，未知字形保留为未确定语种。人物、饰演角色与兼容字段投影共享语言证据，避免 `name_cn` 把繁体或未知原文重复复制到简体槽。

- `tmdb_people.py` 按准确的电视剧、季与可选章节范围读取演员和制作人员，复用人物仓库、手工字段保护、签名预览及一次作品提交。整季使用当季 `aggregate_credits`；限定章节时合并选中章节的 credits，不扩大为整季。请求最多 3 个并发，受整体时间预算限制。人物详情失败时仍可使用已取得的姓名、饰演角色等最小信息，失败字段和列表不会清空已有资料。TMDB 的现实演员保存为 `type=person`，饰演角色名保存在当前作品的 `people_refs.character_name`，不会误作动画角色或 CV。
- 演员关系保留官方原角色名 `character_name`，另存中文 `character_name_cn`；原语言取自作品 API 的 `original_language`，中/原语 credits 按人物 ID、类别及 `credit_id` 精确对应，不按名单顺序或仅演员姓名配对。`source_values` 记录上次导入的角色字段，刷新保留手工修改（含主动清空）；旧引用与旧快照继续兼容。人物官方英文名不因收集类型是韩剧而被转写。
- `wikipedia_people.py` 从已经确认、启用的中文维基作品，或本次联合预览明确选中的维基作品补充缺失中文姓名与角色名。纯解析模块 `wikipedia_cast.py` 同时支持演员表、演员章节中的“演员饰演角色”列表、`lk/link-ko`、明确别名及少年演员标记，不把介绍、配音或动物品种链接当作人物身份。仅沿明确的中文演员链接读取姓名证据，不搜索同名演员，也不按名单顺序对应。
- 韩国作品通过 `korean_people_source.py` 跟随上述中文作品的精确韩文语言链接，并核对中韩条目的 Wikidata 身份相同，补充韩文角色原名；只访问固定中/韩维基 API，不访问任意来源 URL。两语角色按唯一 TMDB 演员身份、同一作品及明确年龄标记对应，一人多角需额外精确角色证据；语言字段冲突仅跳过该字段，中文补充不因韩文网络或大小限制而丢失。明确英文原名保留英文，不按国家推测或自行音译。
- 原始响应、修订、跨语言身份、署名与逐项补充证据进入同一个已签名人物快照。预览不改作品/人物 DB；确认仍复用原人物导入与作品保存接口，完全离线应用，保留手工修改和已有资料。更新代码不会自动改写旧记录，需重新预览“更新人物信息”或“刷新作品数据”并确认保存。未能解析、演员未对应、来源失败的具体条目和原因进入处理详情与日志。

- 主角、配角、客串分组展示角色卡片（图片、原名、CV），点击姓名打开共用人物详情弹窗。制作人员按当前作品的职责分行，不拿人物的全局职业代替作品职责；同一职责内去重，长名单可展开，没有独立列表滚动条。
- `people_assets.py` 为人物图片来源适配器，复用 `assets.py` 的限时下载、代理、图片解码校验及内容寻址缓存。仅接受 Bangumi 人物 CDN 的 `pic/crt` 路径及可选数字 `r` 版本参数，或 TMDB 固定 HTTPS 图片域名的受限头像路径；不允许重定向到任意地址。显式预览时有界并发下载，复用已有相同图片，失败保留原图；确认只读取已签名快照，不重新联网。人物 YAML 的 `avatar` 引用 `data/features/people-catalog/assets/<SHA-256>.<扩展名>`，浏览只请求本地 `/api/catalog-library/people/assets/…`。
- `people_birth_dates.py` 集中处理原始生日与结构化日期，按实际精度保存年份、年月或月日，校验公历；识别来源将 `1961年` 错拆成月份 19、日期 1 的情况，恢复年份并移除错误日期。来源冲突记录警告，不补默认月日，也不覆盖手工修改（包括主动清空）。已兼容的格式进入 INFO 日志，未解决的问题在页面汇总，详情进入统一处理记录。
- 人物页已移除“检查本地生日资料”入口；来源导入仍会校验可选生日字段，缺失字段不阻断其他资料。

- `apps/features/people-catalog/backend/people_catalog` 是独立可复用的数据模块。`PeopleRepository` 负责读取、版本校验、批量保存和历史备份；不依赖作品库 UI。
- `data/features/people-catalog/db/person_<稳定ID>.yaml` 每个文件存一个实体；展示分类使用 `taxonomy`，旧 `type` 与 `kind` 仅兼容既有身份和来源。不在打开页面时初始化或联网；无身份歧义的新资料卡在导入预览中默认选择创建，最后统一确认写入。
- 作品仅保存 `people_refs`（人物 ID、类型、职责、来源作品），不复制人物简介。角色的 `voice_actors` 保存声优 ID 和作品范围，同一角色在不同作品的配音分别维护。
- 原始来源快照保存在 `data/features/people-catalog/sources/{bangumi,tmdb,wikipedia}/<SHA-256>.json`；已退役来源的旧快照保留。作品与人物 YAML 是显示权威，来源快照用于追踪、预览和校验。
- 同步按来源类型与 ID 识别实体，不按同名合并；保留偏离上次导入值的手工修改、手工声优关联及其他作品的关联。预览逐字段展示差异；确认阶段检查签名、作品与人物版本，再经统一作品 DB 保存接口写入引用。确定作品未提交时回滚人物更改；若作品提交或回滚状态不确定，保留人物依赖并报告需要核对，避免制造悬空引用。已有记录保留历史备份。
- 来源的可选字段无效时留空并记录具体警告，不阻断其他资料。读取失败不能清除已有的本地资料、角色或 CV 关系。身份、签名、路径范围与本地版本等安全验证仍严格执行；确认阶段不重新联网。

已有资料卡与作品关联分别判断：资料相同但本作品缺少关联时，明确来源身份、依赖完整的候选默认补回作品关联并折叠，可展开取消，最终通过同一保存接口补回；不会重复建卡。已有关系不重复追加，同名、职责或角色依赖有歧义时不自动勾选。旧关联缺少 `credit_id` 时只接受双方唯一、同源同人同职责同角色的兼容匹配；不能把缺少字段视为任意匹配。

旧作品取得本地 UUID 后，即使清空了作品人物关联，仍可按旧版来源范围、演员身份和演职员 `credit_id` 精确认回原角色卡；无 `credit_id` 时还需原始角色名完全相同。仅认可仍有明确来源所有者且原始证据唯一的旧角色，不按同名合并、不跨其他作品 UUID 继承，也不覆盖现有明确关系。找回结果仅进入预览并记录日志，统一确认后才补回作品关联。

无 `credit_id` 的 Wiki 角色补齐韩文后，若同作品、同来源范围、已确认演员、唯一饰演与原中文角色证据均一致，可恢复原角色 ID；繁简转换使用快照保留的原始角色单元格作证据，不按译名猜测。跨 TMDB／Wiki 的已有角色卡仅提出对应建议，不自动合并。仅有资料、缺少演员关系证据的历史角色作为待核对候选，不直接创建重复卡。

演员关系和角色来源可保存 `qualifier`（明确的童年、少年、年少、成年、老年阶段）及 `role_group`（同作品、同来源的角色分组证据）。同一演员表角色格明确列出的多年龄演员可共用新角色卡，各演员和阶段分别保留；剥掉年龄后名字相同不构成合并依据。已有多张独立卡仍须显式合并；跨来源唯一的作品、演员、阶段及角色证据可以关联已有卡，不能用弱同名扩大候选。相同来源身份只补齐缺失的阶段证据；明确不同阶段在预览中指出差异，不默认采用，手动确认后分别保留，不覆盖旧关系。制作人员职位与剧情角色名称按来源 cast/crew 结构分开处理。

Wiki 姓名解析优先真实姓名字段，不使用条目消歧标题作为显示名；本名、艺名、原语与汉字形式逐项判断，不把整个本名字段继承成韩文。已支持演员单元格的格式包装和明确年龄分支；存在童年演员不表示未标注的主演员必然饰演成年阶段，未明确的年龄留空。多名角色格、无法安全解释的组合保留原始证据和未决警告，不静默丢弃，也不擅自删除名字尾部数字。

接口为 `POST /api/catalog-library/people/preview` 与 `POST /api/catalog-library/people/apply`；前者联网但不修改作品/人物 DB，后者仅应用已签名的本地预览。`service.detail` 聚合本地人物与 CV；`frontend/people-panel.js` 只负责展示，不承担数据存储。

旧本地生日修复 `POST /api/catalog-library/people/birthdays/preview` 与 `/apply` 保留兼容，不再从人物页触发，没有隐式数据迁移。图片 GET/HEAD 只读取经校验的普通缓存文件。

## 豆瓣评分补充与旧数据兼容

豆瓣只保留作品关键词、条目链接 / ID 搜索和评分补充。预览与确认只接受 `metadata.ratings.douban`（分数、人数、来源链接、取得时间），不更新作品名、别名、简介、章节、人物或图片。作品标题只用于检索消歧与来源标签；确认评分不会自动添加别名。公开请求需要登录或验证时可用评分专用浏览器读取当前作品，不跳转到人物页。

桌面评分读取会交叉核对当前作品的可见评分区与有效 JSON-LD 评分。单独附加脚本的 JSON 语法损坏只跳过该脚本，不能因此抹掉已有的有效评分候选；不会尝试修复损坏脚本或从中用正则提取分数。其他有效脚本仍须完整检查，评分／人数冲突返回 `rating-conflict`，结构数量／深度／体积超限继续拒绝，没有可靠评分也不生成零分预览。处理日志仅记录评分来源类别和已跳过的无效脚本计数，不保存原始脚本内容。

评分窗口由桌面壳保有独立登记。用户发起读取后，前端每 750ms 取回同一作品的异步结果，每轮最多 30 秒；验证、失败或关闭立即暂停，继续或重新打开必须由用户触发。重新打开会丢弃未生成预览的旧采集，重新读取；取消及切换页面会停止轮询。缺少窗口登记不等于原生窗口已关闭，只有同一受管原生窗口的存活证据才能恢复登记，不按标题搜索或隐式重开窗口。处理详情区分等待、验证、失败、关闭和预览待确认，日志记录会话、窗口句柄、操作和原因码，不记录页面 DOM、登录资料或确认令牌。

豆瓣人物搜索、演员详情采集、人物补充与专用修复入口已移除。已有作品和人物中的豆瓣来源记录、图片、原始快照及历史记录仍保留，可继续本地读取和手动编辑。作品来源刷新可以单独更新评分，不改旧人物关联。

人物身份冲突判断位于 `people_identity.py`，有界作品数据库清点位于 `people_inventory.py`，不再依赖已移除来源的专用模块。
